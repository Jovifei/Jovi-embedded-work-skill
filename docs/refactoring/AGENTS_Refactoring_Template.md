# 工程重构执行规则（AGENTS 可合并模板）

版本：v1.1；日期：2026-11-25。详细解释见 [Embedded_Refactoring_Principles.md](Embedded_Refactoring_Principles.md)。

使用方法：先填写本项目约束，再合并到现有 AGENTS.md；没有该文件时再新建。保留已有有效规则，不通过覆盖文件消除约束。本模板只约束本次获授权的工程与任务。

## 2. 总原则

安全和已确认需求优先，保留要求保留的产品行为与参数；用少量明确职责完成重构，使代码易读、易改、可验证、便于迁移 MCU。保持在役工程的可靠实现，按事实做最小修复。

区分结构整理、BUG 修复、已批准功能变化和性能/空间优化。修改前列出目标与验证；修改后记录真实变化，不把动态行为改变写成“仅搬函数”。

## 3. 模块与文件

在本项目采用六任务结构时：sample 负责采样与校准；charge 负责充电、库调用及候选；protection 负责故障与许可；output 负责前台功率动作；debug 负责诊断；mmi 负责交互与配置。main 负责初始化和编排。

各核心职责有自己的 .c/.h。支持文件可以保留；不为转发调用再堆管理器、协调器或 MPPT 包装。驱动按 ADC、PWM、比较器、GPIO、串口、看门狗、时基等职责划分，沿用现有可工作的命名和目录。

文件移动同步工程引用、include、链接和脚本路径，统一大小写。Shared 只放真正共用定义；任务状态保持一个权威入口，文档统一在现有 docs 下组织。

## 4. 硬件与中断边界

应用通过普通驱动接口下达控制命令；硬件事件由 ISR 通过短回调、事件或快照上报，应用在前台消费。不要强制所有调用经过中断，也不要在 ISR 直接执行六个业务任务。

芯片寄存器、SDK 类型、引脚、通道、Flash、NVIC 和 CPU 临界区细节归驱动/板级配置。优先补必要的小接口，避免应用直接依赖整套芯片头。

快速 ISR 不执行 MPPT、复杂业务、Flash 写入或阻塞打印；必要硬件等待有界且有失败关断。串口组帧如在 ISR 中进行，必须有界，业务命令在前台处理。

按实时性安排优先级，说明嵌套和共享数据。临界区保存/恢复原状态，保持短小；volatile 不能替代一致性和事件交接。

## 5. 输出与安全

正常 PWM 和功率继电器动作由 output 统一审核并经驱动提交；硬件和驱动 ISR 必须能立即关断，不等待前台。重新启用只能走明确恢复流程，不复用停机、故障、换档或维护前的旧请求。

提交时核查故障、供电、采样、维护和候选有效性。写清首拍、极性、死区、预装载、CBC 统计/恢复、预充资格、机械等待与超时，改动后验证对应波形和动态。

GPIO 读回不等于触点反馈；原库未换不等于候选和实际输出的动态未变；单一 SRAM 入口不证明 Flash 忙时整条调用链安全。

## 6. 数据、时间、WDT 与 Demo

样本有来源、单位、序号、采样时刻及有效性；重复旧样本不刷新新鲜度。滤波、极值、电流和功率保持相容来源，校准或换档明确失效范围。关键状态有明确所有者。

超时/冷却/计时使用实际时间；连续采样条件使用新有效样本数量。漏服务不补造样本，计量不无限使用旧功率。覆盖回绕、延迟服务和时间源停止。

WDT 反映规定窗口内的控制进展，不以循环次数代替；启动、校准、维护有预算，不要求每圈所有慢任务都推进。

按平台定义 Demo，默认目标按该工程已确定的 CC→CV；目标配置与普通档案独立，后续交互入口未确定时不擅自扩展协议。调整目标同步核查限制及保护范围。

## 7. 配置、通信与 OTA

配置按完整有效版本提交。写失败不能发布半配置、推进已保存计量或静默清空用户选择。区分可选项缺失和介质故障，旧配置恢复依既定策略。

APP/BL 的分区和格式保持单一来源。通信同时校验边界和字段关系，完整帧不被后续数据污染；明确命令生效、ACK 和真实发送完成的时序。

OTA 必须考虑首装、失败恢复、有界重试、非对齐分片、校验和降级。新 BL 的完成凭据要求与工厂工具一起交付，列清新旧 APP/BL 兼容组合。

## 8. 验证与审查

先固定基线和验证标准，再分批修改。检查深度与风险相称，不堆无意义测试；功率、中断、存储和升级改动必须有针对性验证。

分别报告主机检查、当前目标编译链接和实板验证，标明通过/失败/未执行/受阻。历史构建、旧波形和脚本退出 0 都不能自动证明本版合格。

问题写清事实、可达触发条件、因果链、实际影响、位置、复现、最小修复和验证。区分遗留、新增、需求变化与证据缺口，按真实后果分级，不把缺少板测自动判为 P0。

重要修改从功能/架构、功率/中断、采样/时间、存储/通信/部署交叉复核，以证据统一结论。

## 9. 执行、文档与交付

按任务选择本仓库 skill：prj_zl 管目录/构建引用，code_wrt 管代码实施，code_sc 管证据审查，code_zl 管注释与批准的等价整理。各自按需读取资源，缺少可选辅助工具时采用等效方法并说明边界。

已授权阶段通过验证后继续推进；仅在范围或关键产品取舍尚未确定时提出具体问题。可完成工作先完成，不能以缺某项实板条件为由停止所有工作。

区分 skill、规范文档和产品固件版本；纯技能或文档任务不升产品固件版本。交付同步版本说明、任务表、实际参数与调用关系、验证记录，以及受改动影响的学习 HTML/函数说明/图。已指定知识库按约定同步，未做的不得写成已完成。

完整固件交付提供对应源码/工程/依赖、实际构建产物和哈希、修改清单、未关闭事项、部署/回退说明及用户验收步骤。测试替身不混入目标固件，旧产物不冒充当前产物。

## 10. C300 使用本模板时的已确定补充

仅用于 C300：六类应用职责；原 HT32 MPPT 库调用与复位集中 charge；保留 300W、PV10A、CC6A、涓流2A、PV13–55V、周期1200下比较值108–1092及普通12档参数；不吸收 B/165W 的算法与阈值。

采用后续计划的 Lead 三平台 Demo，默认目标57.8/72.3/86.8V；独立目标配置是待补齐要求，不能视为已实现。其余首拍、CBC、预充、IRQ 与 BL 首装细节按当前 C300 合同和对应验证执行，不向其他 MCU/工程直接照搬。

本模板不授权修改其他工程，不保证当前代码已经满足这些规则，也不代替本版审核和实板验收。
