### 既有命令名兼容例外

四项技能保留已有的下划线命令名，如 `code_sc`。当前 skill-creator 官方验证器要求名称采用 hyphen-case，因此直接校验这些旧名称会拒绝。

测试明确验证这一拒绝理由，并只在临时副本中将名称投影为连字符形式，再校验其余官方规则。正式文件没有改名，不能将这个结果描述成“原名直接通过官方全部规则”。选择保留名称是为了避免破坏既有调用方式；独立目录资源检查另行完成。

### 3.3 审查试用的证据范围

该示例明确允许比较器 ISR 在两条前台 C 语句之间插入。报告分别列出两条独立反例：读取事件后清零覆盖了新事件；正常使能在 ISR 关断后恢复执行，覆盖较新的关断命令。计量反例为相同 100ms、恒定读数 P，在 1ms/10ms 服务间隔下分别累计 10P/P。

这些是源码交错和算术推导，没有运行故障注入或板测。报告将 WDT 外部实现缺失列为证据缺口，没有仅凭 `wdt_feed()` 名称断定真实硬件持续刷新。只读审查没有修复示例内的问题；发现示例问题不表示当前产品存在同样问题。

## 4. 验收结论与未覆盖项

本轮资源和脚本检查通过；四项试用在给定输入与授权范围内符合本轮目标。试用验证了已知问题的处理方向，不能证明技能在所有工程中必然给出正确结果。

- 没有执行全部 126 个模型行为场景，也没有做与旧技能的统计对照实验。
- 没有修改或构建 C300、参考 B 工程或其他产品固件。
- 没有目标硬件波形、闭环、温升、故障注入、Flash 掉电或 OTA 实物验收。
- Keil 检查器只检查所列字面路径及成员；动态宏、设备包、特殊路径语义、实际构建选项、命令脚本和链接/向量仍须按其输出与技能合同核对。
- 仓库发布后，用户已有的独立安装副本需要按原安装方式更新整个技能目录，包括 references 和 scripts；单独覆盖 SKILL.md 会遗漏必要资源。

后续更改技能时，应重新运行资源检查，并按所改合同选择有代表性的行为场景；不要直接继承这份记录的通过结论。
