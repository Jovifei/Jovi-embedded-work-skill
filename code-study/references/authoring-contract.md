# 写作与交付合同 · 2.0

## 正文不是函数目录

直接在目标项目文档目录完成真实内容。`learning/`是首要阅读入口，按实际阶段和功能讲明白；目录和阅读任务只是辅助。完整标准见[学习正文设计](learning-handbook.md)。不能先批量生成几百个浅薄函数页，再给learning剩几句摘要。

```text
docs/code-study/<book-id>/
  README.md
  learning/<阶段>/README.md
  learning/<阶段>/<讲解>.md
  modules/  functions/  reference/
  graphs/                    # SVG及可编辑图源，可按阶段再分目录
  index.html                 # 唯一HTML：离线阅读、搜索及源码定位
  assets/                    # 本地资产和递归全文索引
  source_snapshot/           # 原字节学习证据，不是固件交付包
  verification/  study.json
```

不新增每函数HTML、第二套手写正文或两套不同版本索引。旧书只做依据比较，不混入当前事实。默认项目目录交付；明确要求附件/归档时才打包，并包含入口、资产和基线。

## 模块页

解释为什么有此模块、不负责什么；实际参与构建的文件；初始化/主循环/任务/ISR/回调上下文；各函数分组；上下游数据、谁写状态、参数单位、生命周期、正常/失败/再次调用。调用图不等于include图；没发现调用者不能写死代码。模块页必须指回学习章。

## 函数页保留原先的严格顺序

第1节必须为`## 1. 完整函数体与原注释`，展示直接绑定原注释和完整函数，保留缩进、编译条件、所有分支和提前返回；不加教学注释。闭源只给真实声明并说明不可见。

再解释职责、参数/返回、调用者/被调用者；第5节`## 5. 代码解释`才按有意义的逻辑块展示真实片段和教学说明，说明做什么、怎样做、前后依赖、失败和再次进入。保留比较符号、位宽、单位、饱和、资源与并发副作用。详见[函数规范](function-code-explanation.md)。

简单getter可短；不能为字数复制套话。完整源码与讲解片段分开校验。函数图复杂时拆成带定位链接的图组；不要缩到读不清。

## 参数、状态和场景

关键参数必须追到定义和使用表达式。限制值相同但用途不同不可随意合并；控制目标、连续预算、软件保护和硬件额定值分开。示例注明来源和假设，不把理想公式当硬件保证。每个核心功能说明成功、未满足、超时/故障和再次进入；不适用要给原因。

初始化、中断、采样、保护、状态、算法、执行、通信、保存和Boot按照真实范围关联，未知/未提供明确列出。源码、旧注释、历史报告相冲突时保留冲突，不静默统一。

## 四类结论分别给

机械结构、逐章语义复审、实际浏览器/图视觉、固件及实机验证彼此独立。机械检查不证明讲解正确，浏览器跑通不证明状态机安全。统计来自当前磁盘与清单，不固定章节或函数数量，不替用户标学习完成。
