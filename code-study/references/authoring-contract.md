# 写作与目录完成合同

## 1. 要写入项目的是文章，不是Doxygen式清单

全部产物直接位于目标项目`docs/code-study/<book-id>/`。不把ZIP当成交付，不只给聊天目录或模板。所有文章、SVG、索引和进度需要真正写到对应路径，生成工具不得接触产品源码。

合格资料让读者能解释“谁在何时、凭什么数据、调用了谁、改变了什么、失败后怎么办”。函数名、函数头、自动调用树只是证据骨架，不是文章主体。

默认布局：

```text
docs/code-study/<book-id>/
  README.md
  study.json
  modules/                 一个实现模块一篇.md
  functions/               一个函数一篇.md；必要时链接子流程
  reference/               整机、索引、跨模块专题与核心算法详解
  learning/                阶段路线、逐阶段文章、进度、记录模板、结业练习
  graphs/
    modules/               .dot + .svg
    functions/             .dot + .svg
    overview/              .dot + .svg
  index.html               唯一HTML，仅搜索
  assets/                  本地CSS/JS及完整全文索引
  source_snapshot/         默认选择性保留，只读学习证据
  verification/            基线、清单、覆盖、语义复审及浏览器记录
```

不要新增modules/*.html、functions/*.html、reference/*.html、source/*.html。不要发布一个正文阅读SPA来变相恢复HTML文章。

## 2. 模块文章最低语义要求

使用`assets/templates/module.md`，每项有具体内容：

| 项 | 必须回答 |
|---|---|
| 定位 | 为什么有这个模块？它不负责什么？删掉后哪条链断了？ |
| 上下文 | 上电/主循环/任务/ISR/回调？调用频率依据？是否可重入？ |
| 文件边界 | 实现、头文件、配置和外部依赖，哪些实际参与目标构建？ |
| 内部结构 | 全部函数表；初始化、主路径、辅助、错误、清理函数分组 |
| 上下游 | 谁调用谁、输入输出、所有权、有效期、失败传播，不只列文件名 |
| 状态 | 静态变量/ctx/队列/缓冲由谁写、谁读，何时初始化和复位 |
| 参数 | 单位、原表达式、配置条件、0/负值含义，控制目标与保护点分开 |
| 场景 | 正常、失败/退出、重新进入至少各一条；不适用时说明源码原因 |
| 易错点 | 选本模块真实易混淆概念，不套同一“注意并发”段落 |
| 学习检查 | 可从源码验证的题目、产物和参考要点 |

## 3. 函数文章最低语义要求

使用`assets/templates/function.md`。

- 第1节先完整展示原函数头/原注释与完整函数体，保持真实顺序、缩进、条件编译、全部分支和return；此处不增加学习注释、不省略源码。
- 参数逐个列：方向、单位、范围/空值、有效期、所有权、是否修改。`const T *`不自动证明线程安全；未使用参数明确写未使用。
- 返回值逐分支解释；void也要解释外部状态/硬件副作用。0不是统一的“成功/失败”。
- 第5节固定为“代码解释”。按源码顺序分职责块展示真实代码并添加中文学习注释，说明做什么、怎样做、为何这样安排及前后依赖；不是“执行语句/循环继续条件”转录。详细格式见[代码解释规范](function-code-explanation.md)。
- 说明条件真假两支，保留`>`与`>=`、加权计数、递减计数、复位点和早返回。
- 明确同一次调用内状态赋值后，是继续尾部公共段、fallthrough、break，还是立即return；不能只画下一次调用才发生的假时间轴。
- 标注读写集合、锁/临界区、资源生命期、等待上限和异常时不再执行的部分。函数指针可能目标明确列未知，不凭名称猜。
- 正常轨迹具体到输入值/状态→分支→写入/返回；失败轨迹和重复调用轨迹必须受源码支持。
- 关键算式列变量单位、位宽、符号、截断、饱和、运算顺序；浮点/整数差异不得用理想数学替代。
- 每函数配SVG；大函数先给总图，再给局部分支，不能裁掉错误路径。

简单getter可以短写：明确读哪个状态、返回副本还是指针、调用者和生命周期、无分支与并发前提即可。不得用固定最低字数逼出重复空话。

## 4. 反例

不合格：

> `update()`更新状态；先判断参数，然后调用处理函数，最后返回。参见源码。

合格的写法应类似：

> `update()`先检查快照的有效位。无效时清除本次连续确认计数并返回false，因此下一份有效样本不能接续旧窗口。有效时，只有`sequence`变化才增加计数；同一快照再次调用不推进。计数达到门限后只产生启动请求，不直接写GPIO。门限表达式与调用证据见指定行号。

这段是写法示例，不是给其他项目直接套用的事实；实际函数没有这些条件就不能写。

## 5. 学习路线

阶段按依赖关系排序，不按文件字母顺序。常用顺序：整机地图→初始化→调度/并发→数据→参数/领域→状态→算法→执行→异常/恢复→通信/存储→综合。

每阶段至少有：学习目标、前置知识、重点文章与函数、跟读顺序、正常/失败演练、自测题与参考要点、需留下的图表/说明、完成判据。阶段数适应工程，不硬凑14。并行模块可标选读，但不能从声明全量范围中悄悄遗漏。

初始进度全为“未开始”；学习记录模板由用户填写。代码理解通过不等于硬件G0～G15或产品验收通过。

## 6. 核心专题与参考索引

每书至少一篇整机联合介绍、一篇核心算法/业务闭环详解。另按实际需要创建函数索引、宏/配置表、类型/字段表、状态转换、任务/中断、协议/持久化、源码边界、已知未解项等。

介绍算例必须与当前冻结源码一致；参考答案与函数页互链。新专题加入后同时更新总README、相关模块、学习阶段与全文搜索。

## 7. 定义完成

“全部函数”只针对已声明范围、工具能力和构建条件。报告列出：选中源码文件数、已逐函数分析数、仅接口边界数、解析失败/未解析边数、排除项。文件数量只能从当前磁盘和清单统计。

结构检查通过、内容复审完成、浏览器实测、固件测试四者分别给结论。文章仍有未确认硬件条件可以交付学习书，但必须公开限制，不能偷改为肯定语气。

## 函数页阅读顺序

函数页第1节必须先展示完整函数体与原注释，作为本页证据原貌；后续才进行职责、参数、调用关系与代码解释。第1节禁止添加学习注释或省略源码，第5节才允许为了教学加入注释式解释。
