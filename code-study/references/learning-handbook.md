# 学习正文设计：把成功经验变成可执行要求

## 最容易失败的地方

以前容易把“有阶段目录、有函数页”当成“有教程”。读者看到的却只是学习目标、函数链接和自测题，不知道设备正在做什么。另一个问题是用术语概括整个动作，图里又只有状态枚举，读者必须先看懂源码才能看懂教程。

解法不是把标题改成口语，而是把**动作、原因、真实判断、失败去向、跟读例子**全部写出来。不要追求固定篇数/字数；单个简单工具可少章，复杂状态机不能压成三行。读者应能不翻其他页先理解本章主线，再沿链接核对。

## 分组与三层阅读

1. 学习层：按实际阶段和功能，教“现在发生什么、为什么”。目录页简短，正文独立且详细。
2. 模块层：查“谁负责、谁不负责、与谁配合”。每模块指回对应学习章。
3. 函数层：看“完整真实实现及原注释”，再看解释；保留签名、缩进和所有分支。

阶段不是源码枚举的机械复制。一个学习阶段可覆盖多个模块；一个状态机可能拆成准备、开始、正常运行、停止几章；几个独立状态机不能画成同一个变量。RTOS任务、中断和硬件动作也不是串行目录顺序。

## 每篇教程的内容合同

| 必须回答的问题 | 合格内容 |
|---|---|
| 本篇解决什么困惑 | 用一个设备现象或操作开场，而不是术语定义堆 |
| 开始前是什么情况 | 当前状态、有效数据、计时/校准/故障条件、从哪里进入 |
| 为什么不能省这一步 | 源码能证明的前后依赖；设计动机无证据则标推断 |
| 这一步具体做什么 | 顺着真实分支解释读值、比较、计算、写入、返回 |
| 参数是多少 | 当前值、单位、定义处和使用处、模式/档位/编译条件 |
| 等待时在等什么 | 谁启动计时、是否连续满足、何时清零、哪个中断仍可运行 |
| 成功/不成功会去哪 | 原地等待、停止重试、锁住、超时、下一次调用；不能只画成功 |
| 举例如何走 | 假设输入明确，逐步得到中间值、分支和结果；非实测 |
| 哪种理解是错的 | 至少一个本章实际存在的误解或失败场景 |
| 回代码看哪里 | 真实函数、文件和行范围，并说明阅读顺序 |
| 能否复述 | 自测附答案和依据，不替用户勾选“已掌握” |

没有数值运算的章节可用事件轨迹，不硬塞数字。没有故障处理的纯函数要说“本函数不处理故障，由调用方…”，不伪造保护。

## 口语的尺度

| 不要只写 | 先写成这样的动作 |
|---|---|
| 退避 | 这次没成功，先停稳，等规定时间以后再试；计时从哪里开始另写 |
| 合闸/分闸 | 让继电器接通/断开；控制引脚变化与机械动作分开 |
| 仲裁/收敛 | 把这几个限制都算出来，最后采用更小的允许值 |
| 单一Owner | 这个状态只允许谁修改，其他文件只能读取 |
| epoch一致 | 这几项数据要来自同一次检查，不能一半新一半旧 |
| Arm | 按当前代码说明重新允许输出前先清什么、等什么、再检查什么 |
| fail-closed | 条件不确定时不允许启动/输出；到底关哪一路必须说清 |

这些是写法，不是所有项目都这么实现。第一次保留术语对照即可，后文尽量用中文动作。专业标识符不能翻译到无法搜索；`20ms`名义调度不能写成硬件保证响应20ms。

## 图的分层

整机一张地图；每个重要状态机一张主线图；复杂判断再拆放大图。对准备开始、第一次输出、继电器/执行器动作、紧急停止、恢复、设置事务和持久化，用时序图或状态图分别回答不同问题。

节点写动作及函数/状态；边写条件、单位和去向；循环要有退出/超时说明。图下用一段话解释读图顺序和至少一个容易误读之处。不能把原理图截图算成软件流程图；原理图局部必须说明元件、信号与代码的关联。不要把源代码函数表渲染成图片凑“图文并茂”。

## 参数与算例

定义值不是全部：追到实际使用处，看是否有更严格的上限、模式切换、编译开关和保护覆盖。记录比较符号、整数运算顺序、最小非零值、截断和饱和。

例如某个虚构控制器设置输出范围为0或100～900‰：60‰请求不一定会被抬到100‰，实际可能被置0。必须以代码分支决定，不能用常识补齐。所有示例数字都要标为“当前源码推导”或“假设教学例子”，绝不沿用上次产品的数值作为新工程默认值。

## 嵌入式需要贯穿的区别

输入旧不旧、同一块是否被重复处理；ISR与主循环谁能写状态；故障置位与清除谁负责；请求值/软件提交值/寄存器/物理波形；普通停止与紧急停止；允许启动与已经启动；命令受理/内存生效/Flash提交；时间回绕/超时/看门狗；缺SDK和Boot时证据止于哪里。

不是每篇都复制这段清单。各问题放到它实际发生的章节，并在综合排查章用具体现象重新串起来。

## 样章和完成复审

先抽“准备开始”和“停止恢复”两章自审：不看源码能否说明动作？图里是否有失败边？参数能否追到使用表达式？例子能否算回去？讲解和源码是否同一版？不通过先改讲法再批量扩展。

最终每章都记录复审结果，不只是抽查两章。函数量、字数、章节数、图数只报统计，不当质量评分。把全书的实际未解释范围、未知调用和缺失实机证据放在入口；复杂问题没查到就如实保留，不能由“全量函数覆盖”消失。
