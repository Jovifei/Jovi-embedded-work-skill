# 图规范：必须能反向核对到源码

## 1. 必需图与计数边界

每模块一张调用图；每函数一张逻辑图或一个总图＋子图组。复杂度很低的函数允许小图，不为数量绘制无意义装饰。整机至少有分层/数据控制图、启动/运行图和核心联合流程；并发、状态和恢复按实际代码补齐。

SVG是交付格式，DOT是默认可编辑来源。默认脚本检查一张SVG有同名DOT；需要其他图源格式时须调整配置/验证并记录，而不是假名为DOT。

## 2. 不同关系不能混画

| 关系 | 默认图例 | 证据 |
|---|---|---|
| 直接调用 | 实线箭头＋函数名 | 函数体中的调用语句 |
| 注册/函数表绑定 | 虚线＋注册 | 赋值、表项、注册函数 |
| 间接分发 | 虚线＋分发条件 | 分发表调用点＋可能目标 |
| ISR/外部事件 | 点线＋事件源 | 向量表/注册/外设配置，不凭命名 |
| 数据流 | 单独图或不同箭头＋字段/单位 | 生产者、消费点、缓冲/队列 |
| include依赖 | 独立依赖图 | include/import，仅代表静态依赖 |
| 未解析目标 | 灰虚线＋UNKNOWN | 只标可见表达式，不杜撰目标 |

颜色只作辅助，黑白打印仍能通过线型与文字辨别。不要把调用图画成确定时序；异步事件可以出现在两个节点之间。

## 3. 函数控制流

保留条件真假标签、比较运算符、关键参数单位、所有提前return。循环必须有条件入口、回边、break出口和continue目标。switch必须区分break与fallthrough；goto指向真正标签；异常/cleanup路径不得遗漏。

同一次调用内：状态被赋新值后可能仍执行公共尾段，不能强行画成返回主循环后才发生。递归画回边；多次调用同一函数可聚合节点但要标调用点与条件。

没有AST/CFG时由Codex对函数体逐块人工核对，不宣称形式化CFG。参数宏按当前构建条件取值未知时，图中保留原表达式。

## 4. 可读性

主图以竖向为主，避免一张超宽图；节点文字控制为短句，长公式放正文。高复杂度函数分为总览/子流程，正文给明确链接。SVG保留viewBox，字体优先系统无衬线/中文fallback，不把字体文件打包。

节点可链接到.md与函数页，路径以SVG自身位置计算，不以引用文章位置计算。Graphviz的URL使用相对路径与`target="_top"`；不能嵌入script/foreignObject/外部image。

## 5. 生成模板

`assets/templates/flow.dot`与`call_graph.dot`提供字体、图例和布局示例。Codex填写真实节点和边后调用：

```bash
python "$SKILL_DIR/scripts/code_study.py" render --book "$BOOK"
```

先确认所有DOT是本轮自行编写/检查的内容。脚本不会安装Graphviz。渲染成功只说明DOT能生成SVG，不能证明逻辑正确。

## 6. 目视与语义验收

抽查最长函数、switch/fallthrough、循环、跨模块回调、故障打断等代表图；每类至少一张。100%看字与布局，放大看边和条件是否重叠。SVG链接与图片渲染都需实际打开验证。

语义复审必须对照代码：分支是否遗漏、guard是否成立、条件并且/或者是否被画反、返回之后是否还有错误连线、图的边是否只是“设计意图”。记录实际检查的图文件名，不写虚构“全图已看完”。
