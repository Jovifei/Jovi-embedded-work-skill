# 核心算法与状态联合专题

## 目标

用户特别需要能一篇贯通“业务目的→状态→目标/预算→算法→执行→反馈”的介绍。不要仅把module文章拼接，也不要写脱离源码的算法教材。

先识别项目的核心：MPPT/充电、BMS估算与均衡、电机FOC、控制器防逆流、网络请求生命周期、照片推理流水线、事务持久化等。只有源码能支持的部分才进入“已实现”正文。

## 推荐章节

1. 一句话目的与各层职责；哪些约束高于算法目标。
2. 输入/输出和反馈，单位、精度、可信度、数据来源。
3. 并列的多套状态机，各自运行频率、状态和复位范围。
4. 真实单周期调用链，先后、早退、重复样本和异步事件。
5. 参数/档案怎样形成目标；合法性、预算主导与取最小值的域。
6. 状态进入/保持/退出的完整条件；去抖、回差、异常、恢复。
7. 算法实际算式、符号方向、固定点、整数舍入及代码位置。
8. 内部记忆/积分/窗口，何时更新、饱和、回撤、清零。
9. 命令动作和权限，零输出的不同含义。
10. 命令被拒绝或中途故障时谁处理，历史如何保留。
11. 至少三个按源码计算的数值例子，另加一个异常/恢复轨迹。
12. 调试观测量、排查顺序、算法修改边界、已知未知项。

主题规模小就合并章节，不硬凑19节；复杂项目可以一篇总论＋子专题，全部互链。

## MPPT示例提示（不是通用项目事实）

若确为MPPT工程，分别核实`P_allow/P_req/P_meas`、PV域/BAT域、阶段电压收流、MPPT搜索Vref、功率闭环、Duty和实际输出授权。明确CC是阶段，不保证任何光照下实际电流恒定；尾流阈值与充电限流不能混淆。0、负值哨兵必须按当前字段实现解释。

不把旧P300-1的`cc_ma=0`解释复制给采用显式policy的新工程。不默认96%效率或3A/12A/8A是普遍规格。没有BAT_I就不能描述成实测电池电流控制。

## 图组与算例

至少配总链、状态协同、时间尺度、核心算式/闭环、正常/故障动作图；可复用已核对的图并注明视角。文章可直接链接函数图，不强行再画一套相互冲突的流程。

算例脚本只能复算已解释的表达式，不能为了验证把整个未知控制器替换成理想模型。明确输入、初值、宏、期望、舍入和边界。原代码存在疑似Bug时，文章解释原行为并单列风险，不把理想修正行为写成当前实现。
