# 增量更新、续写与发布

## 更新原则

更新前比较旧`source_manifest.json`与实际输入。源码变化后按依赖更新：本函数→调用者/被调者→模块→专题→参数算例→学习阶段→索引→SVG→搜索。实际源码换基线时新建book-id，不能只改旧书标题版本号。

用户学习进度、手工笔记和批注必须保留；基线变化时标“待重学”，不能伪造已掌握。

## 函数讲解版式升级

将旧函数页升级到v1.3时，使用同一冻结基线：

1. 第1节新增/更新“完整函数体与原注释”，从原函数头注释连续展示到函数结束；禁止插入学习注释或省略分支。
2. 第2～4节分别讲职责、参数/返回、调用关系。
3. 第5节保留注释式代码解释；不能把第1节的原函数块直接当作讲解。
4. 更新函数图、全文搜索和内容摘要；旧语义复审失效，重新核对`original_function_body_fidelity`等项目。

升级Skill安装本身不会自动重写项目里的旧学习书。

## 发布权限

生成本地资料不代表允许push。用户明确要求远端时，只stage本次docs或Skill路径，不使用`git add .`混入产品代码。写main必须有用户明确授权；非force更新失败就停止，不回退远端。

发布后核对实际ref、提交和变更范围。CI只运行文档检查时不得称为固件CI全绿。本Skill不生成学习资料ZIP，也不创建downloads副本；拉取后直接使用项目里的文件。
