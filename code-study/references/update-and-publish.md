# 更新、续作与发布

先记录旧资料、当前源码及已有用户笔记。旧文档只参考组织与讲法；新参数和状态机必须从当前基线重新核对。只改变教学表达时保持源码快照和原函数代码字节不变。

同一源码基线继续写作：维护原目录与进度，先检查已完成内容摘要。源码真正变化：新建book-id，比较变化的定义、调用者、参数使用处、状态机、图、相关学习章和产品文档；不拿旧SHA给新解释背书。

重做learning时同步更新总README、阶段目录、模块反向入口、函数相关链接、图目录及全文索引。索引必须递归扫描子目录。升级阅读器时更新`index.html`和对应资产，不只覆盖learning造成打开旧正文。删除生成的过期页前列明替代关系，保留手写批注和用户进度。

写作与渲染完成后重新做check、drift、fingerprint、浏览器实测及语义复审。报告共享同一摘要算法，不把报告本身或截图加入内容摘要形成循环；正文/图/索引变化则旧结论作废。

默认直接在项目内交付，不归档、不自动提交。用户当前明确要求ZIP/聊天附件时才提供完整包与真实路径，归档记录单独保存；不改变默认模式。用户明确要求GitHub提交时，仅提交授权范围，不force-push、不改CI/分支规则、不顺手上传固件/客户资料。skill升级只发布泛化规则、模板和虚构测试样例，不把具体项目参数或源码当成公共资产。
