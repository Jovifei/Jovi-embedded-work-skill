# 写法示例：为什么要等三份新数据才允许开始

**这是一段专为讲解构造的例子，不来自真实产品；50和3不是推荐参数。** 实际任务必须用当前源码重建说明。

## 先用人话说

设备刚拿到一份看起来正常的数据，还不急着开始。先再看两份新的：三份都达到要求，才返回“可以开始”。同一份数据反复拿来检查不能算三次；中间任何一份不合格，都得从头算。

这就像确认指示灯是真的一直亮着，而不是偶然闪了一下。但这个例子检查的是“新样本的数量”，**并没有检查持续了多少毫秒**，不能在文档里擅自写成“稳定100ms”。

## 这个例子到底检查什么

| 项目 | 虚构设定 | 含义 |
|---|---|---|
| 有效标志 | 必须为真 | 无效样本把连续次数清零 |
| 新旧识别 | 序号与上次不同 | 同一份有效样本重复调用不增加次数 |
| 数据门槛 | value >= 50 | 49不合格，50合格；单位在例子中为原始计数 |
| 所需份数 | 3份 | 连续三份新且有效的样本才满足条件 |
| 函数结果 | 布尔值 | 只是告诉调用者“条件满足”，不写PWM或继电器 |

## 跟着数字走一遍

第一次收到序号10、值52，有效标志为真：计数变成1，仍返回假。主循环很快又调用一次，但还是序号10，计数留在1。收到序号11、值51，计数变成2；收到序号12、值50，计数达到3，才返回真。

如果序号12的值改成49，计数就清零，不是“差一点也算通过”。后面序号13即便变成60，也只是重新开始的第1份。这里的比较符和清零位置不能为了口语化而省掉。

## 图应该怎么画

按“样本有效吗 → 序号变了吗 → 值至少50吗 → 连续次数够3吗”画判断；在不合格支路写清零，在旧样本支路写不累计。末尾写“返回允许开始，由调用者继续检查”，不能写“电机已经运行”或“PWM已经输出”。实际交付章节必须配渲染后的SVG和可编辑图源，不能只留下这段画图描述。

## 去哪个函数核对

真实项目中把“有效标志在哪里计算、序号在哪里更新、计数在哪里清零、返回值由谁消费”逐项链接到当前源码行。找不到执行器调用，就写这层证据没有提供，不凭函数名补齐。

## 自己检查有没有读懂

同一份好数据连续检查十次够不够？不够，因为序号没变。三份好数据间隔十秒也算不算？这个简化例子没有年龄检查；真实代码若有超时条件，必须补入图和讲解。返回真就代表设备已开始吗？不代表，还要追调用者和输出步骤。

这个示例只展示叙述深度与边界意识；不是让每章套相同段落，也不是一个完整成品章节。
