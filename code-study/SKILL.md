# Code Study

版本：2.0.0。**先教会读者设备在做什么，再带他找到具体代码。**

## 先读这些约定

开始先读 [学习正文设计](references/learning-handbook.md)、[写作合同](references/authoring-contract.md)、[源码依据](references/evidence-and-baseline.md)。先参考[口语讲解示例](examples/phase-explanation.md)。写函数页前读 [完整函数与代码解释](references/function-code-explanation.md)；画图前读 [图规范](references/diagrams.md)。嵌入式补读 [并发和硬件专项](references/embedded.md)。执行工具前读 [工具与完成检查](references/manifests-and-tools.md)，更新旧书前读 [更新规则](references/update-and-publish.md)。

三个优先级不能反过来：**事实准确 → 学得懂 → 页面和数量好看**。旧书只能参考讲法；不能把旧项目的拓扑、阈值、函数名、24章或445个函数套成新项目事实。

## 1. 明确输入与写入范围

默认在目标项目 `docs/code-study/<book-id>/` 创建文件；`book-id` 用真实版本和短SHA，脏工作区或ZIP附内容摘要。先读有效的项目指令，记录源码来源、HEAD/dirty、构建变体、纳入/排除范围和缺失SDK。只给ZIP时安全解压到新目录，记录包哈希，不覆盖原文件。缺失部分明确写“未提供”，不猜最新实现。

默认只改文档，不改产品C/H、源码注释、配置宏、链接脚本或构建文件。不编译未知脚本、不烧录、不安装依赖、不提交远端。用户本次明确授权的归档或提交另行执行；不得把本次授权写成skill以后都自动推送。复制源码前核实许可，默认不把固件、客户资料、密钥或完整学习包上传到公共skill仓库。

工作区模式直接写入上述目录，不默认ZIP。聊天附件模式或明确要求压缩包时，允许在可写目录交付完整文档包，附入口及基线；不能声称已写到用户电脑。旧`finalize`的项目目录检查只用于工作区模式，不能为了绕过它伪造项目路径。

## 2. 先完成“学习目录设计”，不要先批量生成函数页

先列设备/软件实际经历的阶段，以及每阶段要解决的问题。按动作分类，不按文件名字母排序。例如：认识系统 → 上电准备 → 取得可信数据 → 满足启动条件 → 正常调节 → 真正执行 → 出错停止和再试 → 通信保存升级及长期运行。无关阶段删除，实际存在的功能补齐。

主入口必须是 `learning/README.md`。每个阶段有目录页和完整讲解正文；`modules/`、`functions/`是查询层，不是学习正文的替代品。复杂状态机独立成章，并把预备条件、等待、正常完成、超时、故障及恢复分别讲清。不要把8阶段、24章、每章2张图写成固定配额。

先写两篇最容易误解的完整样章，自查讲法和图再扩展全书：通常选“开始运行前的准备”和“异常停止/重新开始”。有用户反馈就应用到全文；没有反馈时不要停在样章等确认。

## 3. learning必须是教程，不是“请去阅读这些函数”

按 [阶段模板](assets/templates/stage.md) 和学习正文设计写。每篇要让读者独立回答：现在发生了什么；为什么不能跳过这一步；谁读什么值；条件和时间是多少；通过后去哪；不通过、超时和下次调用怎样走；去哪个真实函数核对。

必须有口语讲解、已渲染的图、当前参数和适用条件、具体跟读例子、失败或反例、真实函数入口、自测及答案。没有适用项时解释依据，不强行编一段。不能用“先判断、再处理、最后返回”、固定字数填充或几行链接凑正文。

先说“让继电器接通”，再标源码状态名；先说“这次没成功，停稳以后等一会儿再试”，再解释 `WAIT_BACKOFF`。不靠“退避、合闸、收敛、仲裁、闭环、Owner、DTO、epoch”代替动作。确实需要这些词时当场解释一次。**保留原标识符、比较运算符、单位和时序；口语化不是把条件讲模糊。**

重要节点写“中文动作 + 真实函数/状态”，箭头写条件、单位、计时起点和超时去向。图后必须教读者怎样看图。源码`>`不能画成`>=`；同次调用内继续执行不能画成“下一拍”。区分控制请求、软件提交、寄存器状态和真实物理结果；未测触点/波形就不能画“已确认接通/已正常发波”。

## 4. 建立可追溯的查询层

冻结所选源码原始字节，记录编码、哈希、行数；快照只供学习，不是升级包。函数与调用发现优先用可用AST/语言服务器，缺少时人工核对并列未解析边；不能把正则扫描叫全编译调用图。

模块页解释分工、何时调用、谁写状态、参数和上下游，并指向对应学习章。函数页严格保留既有阅读顺序：`## 1. 完整函数体与原注释`先展示直接绑定的原注释及完整原函数，不改缩进、不省分支；第5节`## 5. 代码解释`才按实际逻辑块解释并加教学注释。两层不能混用：教程先讲场景，函数页先给完整代码。

每条关键源码事实给同一基线的文件、函数和行范围。把源码事实、配置推导、旧文档声明、设计意图推断、未知/待测区分开。注释和活动代码冲突时并列记录，不私改源码或静默“纠正”。遥测章解释已有数据如何只读输出，不为了讲解建议新建镜像结构体；只读也不自动保证跨字段同一时刻。

## 5. 真正生成离线阅读器

Markdown是正文唯一维护来源；只保留一个HTML入口`index.html`，默认在本页阅读、搜索、看图和查看源码，不让用户每次点`.md`都变成下载。资源放本地，不用CDN、在线字体或`fetch()`读取本地JSON。单文件嵌入版仅在用户需要时生成，并单独检查。

使用`assets/search/`和脚本生成索引；**递归包含阶段子目录**。入口包含按阶段导航、搜索、上一章/下一章、可放大图片、函数链接、源码行定位、返回原阅读位置；显示当前基线。原始源码必须作为文本处理，不得执行其中的HTML/JS。标注阅读器支持的Markdown语法，不能静默丢掉表格、答案和源码片段。

## 6. 执行与验收

脚本只做冻结、索引、图渲染和机械检查，**不会自动写出合格讲解或证明代码没BUG**。

```bash
python "$SKILL_DIR/scripts/code_study.py" init --repo "$REPO" --config "$CONFIG"
# 按模板读源、写正文、填写inventory与learning计划后：
python "$SKILL_DIR/scripts/code_study.py" render --book "$BOOK"
python "$SKILL_DIR/scripts/code_study.py" index --book "$BOOK"
python "$SKILL_DIR/scripts/code_study.py" check --book "$BOOK" --repo "$REPO"
python "$SKILL_DIR/scripts/code_study.py" drift --book "$BOOK" --repo "$REPO"
python "$SKILL_DIR/scripts/code_study.py" fingerprint --book "$BOOK"
python "$SKILL_DIR/scripts/browser_smoke.py" --book "$BOOK"
# 人工/agent逐章复审后填写editorial_review.json，再完成：
python "$SKILL_DIR/scripts/code_study.py" finalize --book "$BOOK" --repo "$REPO"
```

机械检查通过、逐章语义复审、浏览器实际测试、固件/实机测试分别报告。任何一项未执行就写`NOT_RUN`，不能靠自测脚本生成语义PASS。浏览器搜索必须找到确实存在的正文，不能用`结果数>=0`验收。复审和浏览器记录绑定同一内容摘要，修改正文、图或阅读器后旧结果失效。完整清单见[复审清单](references/review-checklist.md)。

完成时给实际路径/附件、基线、目录覆盖、讲解与图数量、运行过的检查、缺失证据；数量从文件和清单计算。交付完整入口和资产，不能只换`learning/`却留下旧HTML。续作先读进度并核对摘要，不重建已完成目录或删用户笔记。

需要“产品做什么、参数是多少、在什么条件下生效”的产品类说明，使用独立的`product-doc`。两种文档共享源码基线，但不互相替代。
