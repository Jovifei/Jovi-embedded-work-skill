# 格式、等价布局与执行模板

仅在用户要求相应格式/布局、编辑器配置或多文件整理时读取。纯注释任务保持代码 token、现有配置和未触及代码不变。下面的函数、变量、宏及路径均为操作示例；实际名称、位置和组织方式来自本次项目，不以示例作为重构目标。

## 1. 采用项目格式

先读项目根和目标目录已有 `.clang-format`、`.vscode/settings.json` 及项目规范，确认实际生效的配置。内置 `clang-format` 和 `vscode-settings.json` 是可合并模板，不覆盖当前工程已批准的约定。

采用 Jovi 模板时：

| 对象 | 样式 |
|---|---|
| `.h` 函数声明 | 单行完整声明和行尾中文；`ColumnLimit: 0` 不按固定列宽拆参数 |
| 连续 `#define` | 数值列与行尾注释按块对齐 |
| `.c` 分节 | 短 `/* 标题 */`，不用等号装饰 |
| `.h` 分节 | `//=================== 标题 ===`；下一行即代码；分节间一行空行 |
| 大括号 | 控制条件后换行，`else` 独立行；原有单语句是否补括号另需授权与等价检查 |
| include | 保持已有顺序；不因注释格式调整重排依赖 |

### 用户要求同步配置时

1. 在批准的项目内采用/合并本技能 `references/clang-format` 到 `.clang-format`。
2. 将 `references/vscode-settings.json` 合并到 `.vscode/settings.json`，保留无关设置、用户选择及原有其他语言配置。
3. 检查当前 clang-format 是否支持模板字段；格式工具不可用时明确未执行，不声称 Ctrl+S 已验证。
4. 保存格式化使用项目指定格式器；采用模板时为 clangd。仅配置生效需要时提示重载编辑器窗口，F12 与编译数据库的额外设置按已有 `clangd_init` 工作流处理。
5. 只格式化授权文件/区域，并核对实际 diff；不对 SDK、生成代码或其他模块自动扩展。

```c
#define SAMPLE_CHANNELS 4U    // 本例扫描通道数
#define REPORT_PERIOD_MS 500U // 本例上报周期（ms）
```

数值仅示例；不能为对齐改变宏值或表达式。日志字符串、协议文本和 `__LINE__` 的行为也要与授权范围一致。

模板控制换行、缩进与对齐，**不会自动插入大括号**。不要把保存格式化当作新增括号或声明移动的语义证明。

## 2. 授权布局的等价检查

### 文件级声明

采用项目约定时，可按「include → 私有宏 → 私有类型 → 文件级静态变量 → 必要原型 → 函数定义」组织。先识别文件级对象，排除函数内 `static`。

移动前逐项检查：

- 原声明和目标位置在同一个作用域、同一个条件守护内。
- 类型、宏、属性、初始化依赖与声明可见性不变。
- 不跨 `#if`，不为集中声明移动/拆合整个条件块。
- 不移动函数体，不把私有状态导出到头文件，不创建新的公有配置头。
- 不能证明等价时保留并报告；结构调整按已授权 `code_wrt` 处理。

```c
/* 静态变量 */
static sample_t s_sample;

/* 静态函数声明 */
static bool sample_valid(const sample_t *sample);
static void sample_reset(sample_t *sample);
```

这是同守护、依赖已满足时的组织例子。不能把声明搬出原条件编译守护，也不能因它位于某个公开函数后面就直接移到文件开头。

### 大括号

授权采用项目括号风格后，对单语句控制体核对 `if/else` 归属、`for/while` 循环体、宏展开和预处理分支。

```c
if (request > limit)
{
    request = limit;
}
```

上例只有确认原单句就属于该 `if` 时才等价。遇到宏、自带语句或声明作用域变化，不凭缩进判断；保留源码并记录具体阻碍。

### 结构体和 API

项目采用同声明类型集中时，按该约定检查但不在注释任务中重排成员；项目采用语义分组时按其现行规范。结构调整如另已授权，应核对声明类型和原有顺序依赖。固定 Flash/协议/DMA/寄存器/packed/bitfield/ABI 布局按实际约束保留，不能按宿主机 `sizeof` 断言目标节省多少 RAM。

函数形参顺序、公开 API 名、类型归属、字段重排、宏删除和新增嵌套结构属于结构修改。用户已明确要求这些动作时分成独立实现范围，不再次询问同一授权；用户只要注释时只报告。

## 3. 单文件与暂存范围

按顺序完成：

1. 读取文件全文和已有注释，再读取当前任务的基线/diff。
2. 明确完整文件、函数、暂存差异或指定提交中哪一版是注释目标。
3. 为所选范围核对函数合同、定义含义、关键控制流和必要 todo，不因为同文件存在旧样式就全部替换。
4. 检查同一事实是否多处解释、是否复制了调用方流程、是否把软件命令写成硬件结果。
5. 纯注释逐文件比较 token/预处理意义；授权格式/布局另核对作用域、控制流和守护。
6. 核对当前源码、Host、目标 build 和板测的证据归属，完成与风险相称的检查后交付。

暂存任务的只读入口：

```bash
git diff --cached --name-only
git diff --cached -- path/to/file.c
git show :path/to/file.c
git diff -- path/to/file.c
```

如果暂存版与工作区在目标行合同不同，不能覆盖现有逻辑，也不能把一份注释同时说成适用于两个版本。给出准确位置与可审阅片段，继续不重叠处。没有写索引授权时不暂存、不取消暂存。

格式或注释检查以本次操作前后的状态作比较，已有逻辑差异另行登记。文本正则去注释可能误删字符串或处理错误宏，不能把这种粗略比较当作严谨的 C token 等价证据。优先使用已有可靠工具；没有工具时如实说明人工 diff 核对的范围和局限。

## 4. 多文件委派

文件不重叠且有收益时并行。主审统一合同、版本和交界检查，Git 写操作由明确分配的执行者负责，避免多个 Agent 同时改索引。

可复制任务模板：

```text
整理 [目标版本] 的 [文件/函数/行范围] 注释。

范围：用户要求 [普通/逐行/指定更细粒度]；允许 [仅注释/明确格式/明确布局]。
只改分配的文件，不改其他工作区修改。Git 默认只读；若主审明确委派写操作，列出仓库、操作和范围。

先读完整文件及相关调用、定义和批准合同。
按项目已采用样式保留唯一接口说明；采用 Jovi 模板时使用 Name/Input/Output/Description，Name 为完整真实签名。
用中文解释上下文、单位、前提、状态/硬件副作用、失败与恢复；简单私有 helper 可省略合同头。
关键分支说明本处后果，同一事实只在定义/合同处解释一次。
不从技能例子继承函数名、文件位置、任务数量、调度周期或硬件行为；命令、设定与物理反馈分别解释。
只为真实未验证/待确定项写 // todo:，注明验证动作和通过标准，并核查历史 todo 证据。
未授权不改状态机、参数、接口、声明布局或格式配置。

完成后报告：文件与实际改动、合同冲突、等价核对、执行过的验证、未执行项及原因。
主审负责统一交界与授权范围内的最终 Git 操作。
```

模板里的默认只读不是对用户已有 Git 授权的撤销；主审可以按本轮任务明确分配，不能再要求用户重复批准。

## 5. 报告模板

先给结论，再列必要证据；小任务可用几句话，不强制制造额外文档。

### 本批范围与变化

- 工程/版本/源码标识：
- 文件、函数和用户要求粒度：
- 实际动作：注释 / 已授权等价格式或布局 / 另行登记的结构或行为修改：
- 保留的既有工作区差异：

| 文件/入口 | 具体注释变化 | 合同或来源 | 未决问题 |
|---|---|---|---|
| 实际位置 | 补充/修正的含义 | 当前调用链/资料/批准合同 | 无，或明确缺口 |

用户需要数量时统计函数头、行内/分节和 todo 的新增/替换/移除；没有实数不编计数，不用注释数量代替完成质量。

### 验证

| 检查 | 本次输入/版本 | 结果 | 证据或未执行原因 |
|---|---|---|---|
| 静态/注释等价 | 当前修改前后 | 通过/失败/有局限 | 实际方法与范围 |
| Host | 对应源码和替身 | 通过/失败/未执行/受阻 | 实际记录 |
| 目标编译链接 | 对应依赖/配置 | 通过/失败/未执行/受阻 | 实际 build/map |
| 实板/部署 | 固件/硬件/工况 | 通过/失败/未执行/受阻 | 实际测量记录 |

仅保留与任务有关的行。纯注释通常无需重新做整套台架，但必须写清没有声称本轮完成这些验证。

### 交付与后续

说明已同步的当前文档、仍待确认的产品行为或硬件判据，以及用户可执行的下一步。历史名称按身份保留，不拿历史文件命中当作活动源码残留。

Git 有授权则完成指定范围的操作并报告真实结果；没有授权时交付工作区变化，不写入索引/历史/远端。不要把「用户要求提交」转成新的确认门，也不要把仅允许本地提交扩成推送授权。
