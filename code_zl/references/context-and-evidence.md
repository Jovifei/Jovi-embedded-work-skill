## 1. 从源码建立局部合同

对关键函数/字段沿读写和调用链回答下列问题，不要求为每个小函数新建一张文档表：

| 问题 | 应能定位的依据 |
|---|---|
| 谁调用、在哪执行 | 主循环、具体 RTOS 任务、ISR、启动/维护路径；回调的实际调用者 |
| 谁写、谁消费 | 定义、允许写入入口、控制/恢复/协议/诊断/Host 消费路径 |
| 数据从哪里来 | 原码、换算值、配置、快照、候选或读回；量纲与有效范围 |
| 何时成立/失效 | 初始化、复位、换档、校准、故障、停机、维护及代次变化 |
| 成功到底证明什么 | 已接受请求、已提交、已写驱动、硬件事件发生或测量通过 |
| 失败做了什么 | 返回/错误码、保留/清除的状态、恢复入口与所需新证据 |
| 依据属于哪一版 | 当前源码/合同/板级配置，以及测试记录对应的构建与硬件版本 |

命名只是线索。`is_ready()` 可能同时推进状态；`preview()` 可能通过指针改正式状态；`diag` 可能参与正常遥测或恢复。先按事实修注释，再报告名字不符；不要为了名字好看反过来猜行为。

检查 `floor/boundary/max` 时分别核实最低许可、计算基准和最终上限。代码把有效上限抬到某个 floor 时，应说明这一中间约束；不能写成永久最大 Duty。理论 CCM 边界也不能据名字写成实际最终硬顶。

安全宏依赖多级 include 时，核对目标构建下实际定义和值；传递 include 本身不自动证明失效。若未定义、宏配置失真或保护路径确被跳过，给出依据和影响；证据不足则列缺口，不能只写「默认开启保护」或直接改 include 图。

## 2. 保护、IRQ 与调度

### 注释实际架构，不强推模板

| 原有模板措辞 | 应采用的核实方式 |
|---|---|
| 必须叫 `Fault_Detection` | 沿当前入口与调用者写真实职责，命名偏好不构成 BUG |
| 检测与恢复必须在同一函数 | 同函数或分开的恢复入口都可如实说明；关键是触发、锁止、恢复资格和执行者清楚 |
| 软件保护全部跟 1ms 标志走 | 核对主循环、专用任务或 ISR 中实际运行的保护，不改成假想调度 |
| IRQ 只能置标志，不准组帧 | 按预算说明有界搬运、组帧、快照、事件与紧急关断；复杂业务在哪执行另查 |
| 使用 elapsed 判断就不算定时 | 写明实际时间源、比较条件和服务延迟，不能仅凭写法判定架构错误 |
| 任务必须都叫 `app_task_*` | 使用当前工程的职责名；main 可以是清楚的任务目录，但不因此新增转发层 |

函数头按实际说明保护动作：仅置故障位、立即硬件关断、发布撤销请求、批准恢复，或真正重新使能。软件保护和硬件紧急路径可能分层存在；不要把两个不同机制误写成重复判据。

若函数包含检测和恢复，可用 `/* 过压检测 */`、`/* 恢复资格 */` 分节；若恢复在另一函数，引用真实入口即可。没有软件自恢复时，核实是否依赖 STOP、维护、复位或硬件解除，再写清实际机制。

### 节拍与 ISR 的事实边界

- bool 节拍标志表示生产者曾置位，多个 tick 可能合并；不能声称消费者精确每周期执行一次。若当前工程用计数、队列或硬件触发，写其实际机制及容量/丢失策略。
- 入口名带 `Callback` 不能证明任务上下文。驱动在 ISR 内同步调用时，回调仍在该 ISR 上下文；任务延后处理则写清交接和消费位置。
- ISR 内有界组帧须说明缓冲上限、完成帧发布、溢出和恢复；不要把下一半帧可覆盖的缓冲说成冻结帧。
- 按实际优先级和嵌套关系说明共享条件；不要把所有中断同级写成通用安全方案。具体优先级数字属于当前 MCU/工程合同。
- 快速 ISR 若有长等待、Flash、复杂业务或阻塞打印，写出真实路径及预算缺口并交审查；不在注释里宣称已经无阻塞。
- 临界区按实现说明保存/恢复的状态与范围；只有 `volatile` 时不能写成已经解决读改写原子性或多字段一致性。

## 3. 采样、时间与状态

### 来源和有效性

样本注释应能区分实际采样时刻、发布时刻与消费时刻，注明序号、有效性和校准前提。代码重复消费旧快照时，不能说得到新采样；刷新处理时刻不能伪装刷新数据新鲜度。

同一个统计窗口的电流、功率、极值和样本数是否相容，要看产生和替换过程。若只复采电流却沿用旧功率，不能注释为同一时刻全套数据；把实际不一致作为问题报告。

重做校准、换平台或清状态时，说明真实失效的窗口、候选和积分端点；旧状态若实际保留，不得用注释宣称已经清掉。

### 时长与次数

| 代码事实 | 正确说明方向 |
|---|---|
| 每次服务将 count 加一 | 服务次数；只有有依据时才能换算实际经过时间 |
| 新有效序号才 count 加一 | 连续新有效采样证据；查无效/跳号/换档是否清零 |
| 按 now-start 判断超时 | 经过时长；注明时间源、允许间隔及回绕前提 |
| 长间隔更新时间但令 dt=0 | 最近处理控制时基，不是最近真正积分 |
| 重复用旧功率补累计 | 如实说明当前补算策略和边界，不能宣称已获得漏掉的新样本 |

整数注释应依据表达式的实际求值类型。强转发生在乘法之后，只能转换结果，不能反向保证中间乘积没溢出。可静态证明边界时直接写结论；未知输入上限才记录需要补充的条件。

### 预览、缓存和状态消费者

- 查间接指针、全局状态和被调函数后才写「不修改状态」。返回快照不等于内部只读。
- 缓存合同写实际比较项：样本序号、配置、模式、温度、校准、时间或上限是否参与；缺少必要输入时说明失效风险，交 `code_sc` 核实。
- Host 专用拷贝、生产遥测、恢复条件、内部算法记忆分别说明。只有 Host 读取可作为结构清理候选，不自动证明可以删除。
- 标志清除与恢复要查是否重新读取新故障/代次。旧清除动作可能覆盖新事件时只报告可达路径；不能靠「已复核」三字把不存在的检查写出来。
- 喂狗注释写实际健康条件、观察窗口及合法长操作的处理。仅主循环在转就喂狗时，不宣称已经证明采样和控制推进。

## 4. 输出、继电器与恢复

### 每一步使用不同语义

| 能确认的动作 | 不能直接推出 |
|---|---|
| 库给出 Duty 候选 | 保护已批准，或硬件已采用 |
| 输出层接受命令 | 引脚已经更新、继电器已经吸合 |
| CCR 写入预装载寄存器 | 当前周期已生效的比较值 |
| MOE 置位 | 必然有波形或已开始传能 |
| ODR 输出命令为高 | 机械触点已闭合 |
| 读到定时器更新事件 | 全部模拟响应与闭环稳定均已验证 |
| 异步模式/某引脚固定低 | 所有负载和工况下电感都在 DCM |

写明实际极性、比较值与导通关系、关断命令、预装载更新和恢复过程。缺少芯片/板级条件时保留未知，不从变量名或别的产品补齐。

若正常 PWM/功率继电器动作归前台统一提交，说明这是正常动作的入口。紧急电气保护可在硬件或驱动 ISR 中立即关断；不能为「唯一出口」把已有紧急路径改成等待前台。

CBC 注释应区分触发来源、硬件动作、软件统计、锁止、扣分及恢复资格。某项目要求 ISR 关断、前台拿新候选恢复时按该合同写；其他项目不能照抄相同门槛、计分和周期。

预充/机械等待之后的判断，核对是否真用了满足时序关系的新样本。GPIO 命令、启动电压资格和机械触点反馈使用不同词。STOP、维护或故障能否撤销未执行请求，按当前实现说明；缺撤销不能写成已防止旧合闸。

## 5. 配置、通信与升级

配置注释写完整配置在哪形成、何时持久化、何时发布以及写失败保留什么。不能把写函数被调用当成保存成功，也不能把缺配置与介质损坏混成一个正常默认路径。

计量保存失败时，核查已保存量、序号、索引和待保存标志实际有没有提前推进；说「失败会重试」必须有对应状态和重试入口。

协议字段除了长度范围，还要查字段间长度关系、完整帧生命周期、CRC/校验范围和缓冲容量。ACK 入队、硬件 TX 完成、对端接收是三个不同事实；注释只承诺代码和协议能证明的那个。

OTA 流程说明准备、状态保存、擦写、校验、完成提交、结果发送和跳转的真实先后。失败后重试、重连、掉电恢复、同镜像重入与版本回退，各按实际实现。APP/BL 共享格式及工厂首装前提要与当前组合一致，不能因为旧版工具成功就写成新版可部署。

本节只指导说明合同与报告冲突，不授权修改 Flash 布局、协议或部署流程。

## 6. 器件与 RTOS 变体

### UART/SPI/I2C/DMA

旧项目中的 UART `STAT/CTL` 快照、读数据清标志、半双工丢回声、overflow drain、IDLE 通知、TX busy 设置顺序等可以作为检查线索。使用前核实目标芯片手册、驱动实现、收发器和实际编译配置，不能把某芯片的清标志序列当通用代码规则。

数组访问前的索引检查、缓冲上限与溢出处理按可达路径核查。未看到问题只保留事实；发现风险给出触发输入和影响，不因参考写法不同就制造 todo。

`__DSB()`、缓存维护、DMA 可见性和多核同步的作用不同。不要写「ISR 末尾加屏障就保证所有核/DMA 可见」；按目标架构、内存属性和实际同步机制说明。

RTOS 的 ISR 通知与调度请求按当前移植层 API 核实。不要未经核对要求所有工程使用相同 `portYIELD_FROM_ISR` 形式、NVIC 分组、栈类型或断言实现。

### main 与任务创建

对于已采用「main 集中建任务」的工程，可在 main 使用 `/* 板级初始化 */`、`/* 创建任务 */`、`/* 启动调度器 */` 分节，并在调用行尾写实际职责。`app_create_task_checked` 若确实存在，说明返回值检查和失败处置；不能为注释新增包装函数或断言。

栈大小、优先级和句柄由实际调度所有者定义；单位是字节还是栈元素要查当前 RTOS。只有项目已明确由 main 管理时，才把 main.h 看作该项目的配置位置。

模块内创建任务、动态创建、私有句柄或 static 入口不自动是违规。按当前需求与生命周期说明，不无条件全局化句柄、去掉 static、导出到 main.h 或迁移任务。若用户另已批准结构调整，转 `code_wrt` 并登记行为及失败路径变化。

## 7. todo 与证据层级

### 具体、必要、可收口

```c
// todo: 恢复后的首次有效输出延迟；验证动作：按本板恢复用例记录触发与输出波形；通过标准：满足已批准的恢复时序预算。
```

此例只有项目确实缺该波形证据且恢复时序在本次验收内时才使用。预算若尚未定义，记录「待确认恢复时序预算及对应工况」而不是填入其他项目毫秒数。

已有 todo 的处理示例：

| 当前证据 | 处理 |
|---|---|
| 已有对应本版/本板/工况的通过记录 | 更新权威验证入口并按范围移除过期行级 todo |
| 只有上周旧源码的 Host 记录 | 不能关闭当前物理时序 todo |
| 对应功能已经删除或职责迁移 | 按真实代码删除失效项或移到新的责任入口，保留必要追踪 |
| 仅与参考工程写法不同 | 核对适用前提；没有真实待确定项就不新增 todo |
| 仅知道未做板测，当前是文案修正 | 集中说明本轮未执行板测，不给所有外设行新增待办 |

### 分开报告四类证据

| 层级 | 能说明什么 | 不能替代什么 |
|---|---|---|
| 当前源码静态核对 | 已检查的合同、调用、类型、条件编译和注释等价 | 运行时序与真实硬件响应 |
| Host | 当前替身与输入覆盖的算法/状态行为 | NVIC、ADC、模拟电流、机械动作或真实 Flash 掉电表现 |
| 目标 build/link | 当前源码与依赖可编译链接，相关地址/符号/map 条件 | 台架、生产部署与物理保护验证 |
| 实板/台架/部署 | 指定固件、硬件和工况下观测到的结果 | 未覆盖工况或另一版固件的自动通过 |

报告必须注明实际执行与未执行项。脚本退出 0 若只是成功复现 BUG，结论应是复现成功而非修复通过；不写「绝对安全」「永无 BUG」「始终 DCM」等超出证据的保证。
