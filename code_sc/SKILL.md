# Code SC

**Version: V0.3.5**

依据本次提供的源码、已确认需求和工程约束审查结构、行为及安全时序。找出真实的职责冲突、状态分叉、并发、边界与集成问题；用尽量小的整改保留已经正确的实现。

**本技能规定审查原则，不提供任何产品的默认实现合同。** 不预设模块数量、文件/函数名、目录、字段、调度方式、算法库、参数或中断优先级。它们须来自当前工程和本次需求。示例中的名字、数值和方案只用于解释原则，不能反向成为其他工程的要求或验收条件。

默认只读。已有修复授权时，核实问题后继续范围内工作；可复用 `code_wrt`，缺少辅助技能仍按本技能完成可做部分。提交、推送和部署遵循会话已有授权与指定范围；不重复索要已给出的许可，不把纯审查扩成写入任务。

## 1. 固定输入、约束来源与审查目标

先读当前项目规则、架构/版本说明及任务，再核对实际文件与构建入口。记录所见内容身份、目标硬件、配置、依赖及可用验证条件。只有片段就说明片段边界。

区分三种来源：

- **保留基线**：本轮要求保留的功能、参数、单位、接口、协议、存储和部署行为。
- **参考或待合入来源**：拟吸收的变化、改善理由、适用前提与依赖。
- **当前结果**：实际审查的工作树、提交、构建配置和产物。

约束必须可追溯到本次需求或该工程的有效记录；技能例子、旧任务决定和参考工程不能代替它。历史问题和通过记录均须与当前内容核对。

| 变更类别 | 审查重点 |
|---|---|
| 结构整理 | 职责与调用映射、状态/硬件副作用、初始化和异步入口、构建引用；保持约定行为 |
| BUG 修复 | 可达触发、因果链、修复前反例、最小修复和相邻路径 |
| 已批准功能变化 | 新行为、边界、失败恢复及兼容/部署影响 |
| 性能或空间优化 | 实际瓶颈，同目标、工具链和选项下的资源/耗时对照 |

调用频率、动作顺序、启动/恢复、限制、模式或协议改变不能仅登记为“结构整理”。已确认缺陷不为名义等价保留；未确定的新行为也不能由审查者补造。

## 2. 审查职责与接口，不按实现外形判定

对关键状态和决策记录产生者、权威归属、允许写入者、消费者、失效/清除条件及执行上下文。多个读者或分步事务可以合理，重点是独立决策者是否争写、重复解释或维护分叉真值。

职责不等于文件。沿用合理的现有组织；只有独立职责、变化原因、状态归属或验证收益成立，才建议拆分。不要由功能名推导固定文件表，也不要要求每种逻辑责任各有一个管理器、包装或数据结构。

检查以下通用关系：

- 业务规则与计算状态的归属是否清楚；调用和重置外部库是否遵守实际接口合同。
- 故障判定、锁止、清除和恢复权限是否一致，是否有旁路绕过规定条件。
- 同一执行器的正常操作是否有明确仲裁；紧急保护路径是否保留所需及时性。
- 数据产生、校准、换算和发布责任是否明确，观察者是否反向修改或重解释业务事实。
- 硬件访问、业务策略、诊断与交互之间的依赖是否与本项目边界一致。

同时看包含、调用、写入及回调关系，不能只凭目录或包含图无环宣称完成隔离。普通命令可由正常接口下达；异步事件可通过有界回调、事件或快照交接。检查实际上下文、寿命和副作用，不强制所有调用经过中断。

接口采用标量、结构或一致快照由真实需要决定。不按参数大小、函数长度或结构内出现某类状态自动判错。保留已确认的 ABI、协议、持久格式、向量及供应商合同；改名、删包装或重排布局前追全体有效消费者。

## 3. 追踪真实副作用与状态生命周期

核对核心操作的输入及隐藏输入、输出、状态写点、硬件副作用、调用者和时机。

- 初始化、重置、开始、停止和恢复各由谁决定、会改变什么。幂等不证明归属正确，有目的的重试与不同时间屏障也不能机械去重。
- 区分计算结果、允许结果、已提交命令、驱动设定和物理生效；可以按实际合同合并阶段，不强制复制成多套字段。
- 返回成功应符合已声明的“发生转移”“请求接受”或“目标已满足”等语义；已经满足目标仍返回成功可能合法。
- 只读、预览和诊断名称不证明无副作用；追间接调用、指针别名、状态推进和正式消费者。
- 内部积分、滤波、去重、缓存、反馈与事务记忆也是消费者；无外部读取不等于可删。
- 合法零、无效、未启用、停止和限制来源按接口合同解释。缓存应覆盖会改变结果或资格的真实依赖，并有更新/失效规则。

## 4. 审查执行边沿、并发与实时约束

涉及危险执行器时，还原首次可能动作、保护建立、正常提交、紧急停止及重新启用的有序路径。稳态存在保护不能证明首次、末次或恢复边沿满足要求。

正常仲裁与紧急保护可以有不同写入路径；不得仅为统一接口而延迟必须立即发生的关断。检查旧命令、旧许可、旧事件是否能在故障、维护或模式变化后再次生效。

查资格读取到动作提交之间的竞争，事件读取/清空与新事件交错，缓冲发布/消费，多字段一致性及可重入状态。`volatile` 不代替原子性、互斥或一致交接。临界区应保存/恢复原状态，且范围与耗时有界。

审核动作时所依据的数据、故障、配置与维护条件是否仍有效。写前、写后、硬件更新和恢复中断后的检查可能分别保护不同窗口；不能只因值相同而删除。

优先级、嵌套、阻塞、最坏耗时和超时取决于实际硬件与调度。串行循环、RTOS、事件驱动或混合结构均按其合同审查，不为满足本技能改换模型。

首次动作、限幅、变化速率、逐周期保护、预充和恢复只在项目具备相应功能时核查；数值与顺序来自该工程。软件复位、看门狗和掉电的清理能力分别核实。寄存器写入不能代替真实波形或机械反馈证据。

## 5. 审查测量、时间、进展与计量

核对数据来源、单位、采集时点、有效性、标定条件和统计区间；这些语义不要求固定字段名或存储形式。重复读取不能伪造新采集，派生量要与输入相容。校准时机按项目策略核对，包括确有需求的在线校准。

区分真实时长、事件/新样本次数和积分区间。漏服务不能补造测量；积压、缺样、旧值保持、回绕和时源停止须有明确语义。计量不得无依据地把一次读数代表无限缺失时间。

若 WDT 用于监测控制健康，检查规定窗口内的关键进展与超时后果，不仅看循环或函数返回。启动、维护和低频任务的例外应有预算；已停走的时间源不能自证健康。活性证据不等于截止时间证据。

使用当前目标、工具链和负载证据评估实时预算；浮点、合并节拍或某个 API 的出现只构成取证线索。

## 6. 审查配置、通信与部署

配置切换应保持对外可见版本完整，并按本项目合同处理持久化、失败和恢复。区分缺失、旧版可迁移、损坏和写入失败；保存失败不能伪报成功或提前推进已保存状态。

通信同时核对容量、字段关系、数值运算、消息完整性和缓冲寿命。命令接受、结果入队、实际发送和对端确认分开描述；工作量应适合执行上下文，实时保护不能被无关通信拖延。

若涉及多镜像、引导程序或升级，核对其真正共享的分区、格式、校验和兼容合同，以及实际链接、镜像和配套工具。覆盖实际需要的首装、升级、断电/失败恢复和回退，不能只验其中一条路径就宣布可部署。

## 7. 审查合并结果与完成证据

合并、变基和冲突解决后的内容是新的审查对象。父分支各自通过不证明组合正确；核对交界处的接口、类型、状态编码、动作资格、异步入口、构建成员、测试、文档和部署依赖。

安全条件要追到当前编译单元中的有效定义和可达分支；缺直接包含只是线索。异步入口要追到当前实际链接实现与消费者；仅有默认声明不能证明运行时会进入默认处理。

按风险选择搜索、严格编译、静态分析、主机测试、目标构建和实测。低影响文字整理不堆无意义测试；功率、并发、存储或协议修复需要能暴露实际问题的反例与回归。脚本退出成功不自动证明被测行为正确。

证据绑定最终内容身份、配置、依赖、命令和覆盖条件。必要条件缺失时完成其余可做工作，列出具体阻塞和验收入口；不把旧结果移作本版证明。

## 8. 结论、严重度与报告

每项问题写明位置、当前事实、约束来源、可达触发、因果链、实际影响、证据、最小修复方向和验证标准。区分继承问题、本批引入、批准变化、未完成需求与证据缺口。

结论类别独立于严重度：**可确认 BUG / 结构问题 / 需补证据 / 需实物证据**。结构问题不一律降成风格，缺少一份验证也不自动升级为故障。

| 等级 | 依据 |
|---|---|
| P0 | 有证据支持、可达的硬件损坏或人身风险链 |
| P1 | 核心使用功能或关键数据完整性失效 |
| P2 | 局部功能、计量、计时、恢复或其他具有具体影响的缺陷 |
| P3 | 维护、兼容、诊断、可读性问题；实际阻断交付时按后果重评 |
| 证据缺口 | 必要事实或验证未提供，列待核项，不自动称 BUG |

报告根据范围提供源码身份与约束来源、问题表、必要的职责/时序关系、分层验证及剩余事项。小任务不强制全部大表，不将本技能的术语或示例结构变成额外交付要求。

源码事实、主机、静态分析、当前目标构建和实板证据分别标明通过/失败/未执行/受阻及覆盖范围。可采用 `SOURCE_CONFIRMED`、`HOST_PASS`、`TARGET_BUILD_PASS`、`BOARD_PASS` 等标记；任何一层都不等于绝对无 BUG。

本版移除产品专属默认合同，所有具体实现均由当前输入确定；带名称和数值的举例集中于示例和评估材料。
