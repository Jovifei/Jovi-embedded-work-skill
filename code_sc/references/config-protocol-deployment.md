# 配置、通信与部署

在配置切换、非易失存储、通信、引导、升级或首装验收时读取。只应用工程实际具备的功能；格式、分区、校验算法、模式、文件名和处理顺序从本项目取得。本技能不规定统一的记录结构、协议或部署方案。

## 1. 完整配置版本

追请求校验、候选构造、运行许可、保存/验证、有效版本发布和结果返回。保存后生效、运行原子切换后异步保存等策略都可能合理；核对其批准的成功、失败、恢复及掉电语义。

需要回答：

- 哪些参数必须属于同一有效版本，切换时是否出现新旧混用。
- 切换期间各消费者看到什么，何时整体采用新配置。
- 保存失败是否保留可用旧状态、回退或进入规定限制，返回结果是否真实。
- 记录缺失、格式不兼容、数据损坏及写入失败是否区分。
- 默认值是否仅在允许情况下使用，是否会覆盖有效用户选择。
- 配置变化是否影响待执行动作、统计、缓存或硬件资格，这些影响是否完整处理。

模式之间共享参数或独立配置由需求决定。独立的数据责任不自动要求新模块、设置协议或存储格式；控制目标与安全范围需要相容，不能为实现某个模式擅自放宽保护。

## 2. 非易失存储与维护

还原实际的准备、写入、校验、发布和清理路径，包含所采用的版本、冗余或提交机制。掉电/失败后要有明确状态；返回成功必须符合接口约定，不能仅凭返回值数值猜测。

保存失败不能提前宣称数据已保存，或丢失必要的待保存标记、索引和恢复信息。重试与介质寿命符合预算，不用无限重试或静默恢复默认值掩盖失败。

维护事务包括进入资格、相关动作撤销、必要的数据失效、异步/存储忙影响、健康监测、失败状态和退出资格。恢复不能未经核查复用已失效的旧命令或许可。

运行期间是否允许继续控制、是否需要暂停采集或停机，应有硬件与实时依据。审查其所有入口，不能把一种产品的维护策略推广到其他工程。

## 3. 通信边界和消息生命周期

列实际缓冲、消息和队列的容量、归属、发布/释放与溢出规则。组帧、解析和命令执行的位置依当前调度与预算确定，阻塞或复杂工作不得破坏其上下文约束。

逐层检查：

1. 声明长度、实际收到的数据、头尾和校验覆盖之间的关系。
2. 内层数据、偏移、总长、剩余空间及分片规则。
3. 整数运算、符号、单位与对齐；访问前完成必要校验。
4. 发送/接收端、应用/引导或转发节点是否按同一合同解释字段。
5. 完整消息消费前能否被后续数据覆盖；重连、拆包、合包、重复、丢失和超时如何处理。

每个长度分别小于上限不能证明彼此关系正确；具体关系依协议定义。设备执行上限也不等于协议合法编码范围，转发或显示路径不能擅自采用本机执行限制拒收。

命令接受、处理完成、结果排队、硬件发送及对端确认是不同事件。按协议确定复位/切换前等待条件和有界失败路径；无关通信不能阻延必须及时发生的安全动作。

## 4. 多镜像和升级事务

若有应用、引导或其他镜像共享分区、格式、长度和校验，核对权威来源及实际构建结果。一个定义的改变可能同时影响链接、打包、烧录、升级和旧版本兼容，不能只改一处声明。

还原实际升级顺序及失败分支：准备、必要的持久状态、擦写、校验、完成发布、通知和交接。后续破坏性操作依赖某项成功时，失败分支不能继续假定其成立。

按本轮变化覆盖边界分片、字段关系错误、重复/丢失、重连、重试预算、校验失败、掉电恢复及回退。成功复现一次失败不表示升级功能通过。

镜像运行资格、入口与地址范围、中断/外设状态及看门狗要求依芯片和启动合同取证，不能臆造通用跳转步骤。

## 5. 首装、兼容与交付

升级后可运行不证明初次安装可运行。若新版本要求元数据、签名、完成记录或其他启动条件，核对工厂/首次部署是否实际产生这些内容，工具与镜像是否匹配。

按真实产品列兼容组合：部署组件版本、配置/记录格式、启动、升级、回退和配套工具。一个组件的更新不自动更新其他组件；不支持的组合需有明确处理。

发布范围内核对镜像、升级包、依赖、工具、迁移及回退说明。具体格式只属于本项目，不由历史案例或技能自动补全。

分别记录源码/主机、当前目标构建、存储失败/掉电实测及实际安装流程。缺证据列待核项；只有当前因果链证明流程无法使用时，才报告相应功能故障。
