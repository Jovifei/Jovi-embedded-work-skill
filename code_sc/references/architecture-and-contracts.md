# 职责、接口与结构审计

在职责、文件组织、库边界、接口、命名、布局或冗余审查时读取。以下规则不规定模块数量、文件名、函数名、目录、前缀或算法实现；这些选择来自本次项目合同。具体代码例子见 [examples.md](../examples.md)，例子不能作为默认合同。

## 1. 职责与依赖取证

建立必要的职责表：`对象 | 权威归属 | 允许写入者 | 产生者/消费者 | 清除/失效 | 上下文`。同一状态可有多个读者，同一事务也可分步执行；要发现的是不同决策者争写、不同规则解释同一事实或未经约定的状态副本。

- 沿业务阶段、计算状态、故障、测量、配置和动作资格的实际写点追责；名称只是线索。
- 已约定为纯计算的部分应遵守其边界；已约定集中编排或由厂商固定接口表达的部分，不因名称相似强拆。
- 调用者提出业务意图，被调用方维护其私有实现；越过接口改私有状态或猜写外部库字段时，给出真实路径与后果。
- 同一生命周期变化被多处独立解释，需核对决策是否分叉；幂等不能免审，合理重试与不同时间屏障也不能机械删去。
- 规则改变若必须散落多处，查权威来源、消费者和分叉风险；不单凭文件数或调用数判错。

同时查包含、调用、写入和回调关系，必要时用依赖图辅助。重点是低层是否依赖上层私有策略、观测是否反向耦合业务、同级是否越权改状态。中立事件回调可以合理；记录执行上下文、数据寿命和工作量。

对关键硬件动作、故障清除、阶段迁移、库初始化和事件交接列全部写点。正常操作的仲裁与紧急保护的及时执行分别核查，不把紧急关断自动当成职责冲突。

## 2. 接口和真实副作用

记录核心操作的输入、隐藏输入、输出、状态修改、硬件影响、调用者及调用时机，核对声明、实现、注释和调用者一致性。

| 线索 | 要补查的合同 |
|---|---|
| 接口接收较大的上下文对象 | 真正使用的数据、可变性、一致性需要、私有状态泄漏和 ABI |
| 已传快照又读取实时状态 | 是意外混用时点，还是有意的提交瞬时复核；批准结果如何失效 |
| 无参函数读取静态变量 | 是本职责的私有实现，还是伪装成纯函数或隐藏跨模块输入 |
| 自称读取、预览或诊断的入口 | 是否修改状态、推进计算，或通过共享指针写正式对象 |
| 成功返回 | 表示实际转移、请求接受还是目标已满足；调用者需要哪种语义 |
| 零值、有效标记或执行状态 | 是否混淆合法值、未启用、无效、停止请求、命令与物理反馈 |

参数和数据结构选取以真实边界为依据。已有一致快照、稳定 ABI 或统一数据合同可保留；不强制按字段拆新结构或头文件，也不将每层状态复制成新的真值。

计算候选、允许结果、已提交命令、驱动设定和物理动作是不同证据层次。实际合同可以合并某些阶段，不要求五套字段；写入寄存器不能自动证明机械动作或波形。

## 3. 冗余、简化与观测

删除或合并前记录：`候选内容 | 语义/单位 | 真实消费者 | 输入身份/时点/有效性 | 副作用 | 保留/合并依据`。当前数值相同不证明测量与限制、即时与历史、业务约束与独立硬件保护相同。

- 内部积分、滤波、去重、缓存、反馈和事务记忆均有真实用途，不能只查外部读取。
- 仅供测试观察的镜像可按授权收窄，并迁移测试到真实行为；旧夹具不能反向强迫恢复已删除接口。
- 只有声明没有生产者的编码，可能是遗漏、ABI 保留或未实现需求；判定缺陷须有当前要求与可达路径。
- 诊断和遥测按已批准用途、接收端、单位、默认配置和预算检查，不按名字一律删除。
- 观察或对照代码进入生产资格和恢复决策时，核对是否有需求依据。
- 短包装可能承担 ABI、异步入口、集中动作、恢复握手或语义边界；不能按行数判断无用。
- 相同数值的写前、写后和硬件更新检查可能保护不同时间窗口；合并前要证明约束仍成立。

同一业务规则有清楚的权威来源。独立安全规则可保留，但需区别职责和依据；厂商内部参数受接口和 ABI 约束时，查其支持的配置方式，不要求猜写私有状态或替换已要求保留的库。

## 4. 命名、布局和外部兼容

遵守当前工程已确认的命名规则。技能不规定前缀、大小写或函数后缀；供应商、向量、回调、协议、持久化及汇编名称按实际外部合同保持。

改名应覆盖声明、定义、全部有效调用、注册、构建、测试、工具和文档。区分活动旧名、兼容入口、外部名和历史资料，不以搜索结果归零为目标。

布局调整仅在有授权和明确收益时审查。核对项目样式、全部初始化器、尺寸/偏移、序列化、内存拷贝、持久化、DMA、寄存器、打包结构、位域、汇编和库 ABI；不要将一种成员分组方式作为通用要求。固定外部布局不得因整理美观而改变，没有目标证据不承诺内存收益。

注释说明实际上下文、单位、前提、副作用、失败和时间要求。名称与描述是待核声明，不是行为证据；注释错误与实现错误分别报告。

## 5. 配置与头文件

按业务规则、硬件配置和公开接口的实际职责找权威来源；不预先指定配置文件表，也不以聚合头汇集全局变量来掩盖职责不清。

公开头暴露真实消费者需要的合同。独立头、私有定义或既有文件均可使用，依据稳定接口、多消费者和依赖关系决定。符号可见性应有可解释的稳定来源，不能依赖偶然包含顺序。

对条件编译追当前编译单元的实际值、工程定义、覆盖关系与可达分支。缺直接包含本身不是运行故障；只有保护实际被关闭且可达时，才据影响分级。保留所需编译检查，已授权移除的具体禁令不能换一种手段偷偷恢复。
