# 功率与中断时序

在 PWM、CBC、继电器、故障/维护恢复、复位或 ISR 竞争审查时读取。依据本工程硬件与合同还原实际路径；下述顺序是要回答的问题，不是给所有 MCU 套用的寄存器操作配方。

## 目录

1. 写点与否决可达性
2. 首拍、末拍及重新发波
3. ISR 与原子交接
4. CBC、预充和复位

## 1. 写点与否决可达性

列 `寄存器/API | writer | 上下文 | 正常/紧急 | 准入条件 | 可恢复者`。前台正常 PWM、功率继电器由 output/明确执行 Owner 审核后通过驱动提交。硬件 Break/比较器及驱动 ISR 立即 hard-trip，不等待队列/前台，不在 ISR 执行完整 output 或 charge 状态机。

ISR 可记录最小 latch、epoch、事件和计数供前台归档；复杂政策、库计算/复位、Flash、阻塞日志留在前台。正常功率统一提交不限制 LED 等非功率 GPIO。软件关断不代替硬件所需的快速保护。

对 `power_inhibited/maintenance_busy/settings_pending/storage_blocked` 等列矩阵：

| 入口 | 当前禁止条件的实际消费者 | 是否受旧候选/并发影响 |
|---|---|---|
| Start / AutoStart / Restart | 文件/函数与读取时点 | 当前 epoch/配置/样本？ |
| PWM arm / nonzero commit | 最终驱动准入 | ISR 后会不会重新开？ |
| Relay close | 执行时资格复核 | 同轮 STOP/故障能撤销？ |
| Maintenance / Reset / OTA | 进入和退出顺序 | 失败能否绕过禁止？ |

若只有 producer 而危险入口不消费，说明该门是否是已要求的保护、是否有等价现有门以及实际可达后果；“以后会用”不能证明当前功能完成，单纯未用声明也不自动是 P1。

## 2. 首拍、末拍及重新发波

从当前源码与硬件配置记录有序事件、执行上下文和可插入 ISR 的窗口：

| 边沿 | 必须回答 |
|---|---|
| OFF → ARMED → ACTIVE | 哪条语句/自然更新首次可能输出能量？比较器/Break/live window/guard 在此之前是否已建立？ |
| 候选 → CCR/设定 → 输出 | 极性、比较值与实际导通、预装载、更新事件、死区、关断值分别是什么？ |
| safe → fault → hard-trip | 谁立即关断？尚存脉冲时是否提前关闭唯一快速保护？ |
| ACTIVE → stale/HOLD/OFF → 恢复 | 旧候选、旧合闸请求、保留库内存是否能未经新资格直接生效？ |

第一次发波之外还要审第二次。保留算法历史可以合法，但不能据此跳过项目规定的首拍/新候选/恢复条件。首拍 cap、rebuild、ramp 应由实际执行责任方实现；若项目没有这种要求，先证明其必要性和允许的闭环变化，不直接添加统一斜率。

示例：前台 supervise 看到 MOE=0 清 `seen_high`，随后 arm 并输出，下一次 task 才置 `seen_high`；若 IRQ 在此期间因 guard 早退、且没有其他有效硬件保护，则存在首拍保护缺口。报告确切可达链及后果；不能因形状直接固定 P0/P1，也不能以稳态 ISR 存在判安全。

将数值处理与时间屏障分开：限幅/单位转换可归唯一 Owner；采样时效、fault epoch、写前复核、预装载自然更新确认、写后/恢复中断后否决可能各阻止不同竞态。合并前必须证明各窗口仍受保护。

最终输出可合并批准与提交，但应明确所消费的同代采样、fault mask/disposition/pending/epoch、维护状态和候选身份。二次 protection 后不能只刷新 bool/epoch 却保留旧 mask 或 disposition。

## 3. ISR 与原子交接

逐个列 ISR early-return guard：`initialized/window_open/seen_high/armed/pwm_active`；追谁置位/清零，以及相对实际输出的时点。对读硬件后置 guard 的序列检查：

1. 主循环读 HIGH。
2. 下降沿 ISR 抢占，读到 `armed=false` 后早退。
3. 主循环再写 `armed=true`，事件已经丢失。

只有查到实际可抢占、guard 和硬件锁存/补读语义才定性。`volatile` 不能修复此类握手。可选修复为驱动拥有的原子事务、硬件 latch、短临界区或单向事件机制，按 MCU 合同选择，不硬塞一种方法。

检查以下并发关系：

- ISR/前台的 fault 位图、epoch、clear 与新事件交错；旧 clear 不得覆盖新故障。
- ADC/DMA 缓冲的写入、冻结、发布和消费；seq/时间/有效性须与数据一致。
- PWM shadow、CCR、MOE 和 applied 含义；读回设定不能证明生效。
- STOP/recovery、维护进入/退出与普通控制同轮冲突。
- 临界区保存并恢复原中断状态，避免无条件 enable；不能包长计算、Flash 或整个业务。
- ADC 等硬件等待可有界，但须说明超时和安全失败路径。
- 快速链不做 MPPT、业务解析、Flash 或阻塞打印；有界 UART 组帧与短回调依预算判断。

按保护及时性、控制截止时间及通信负载审优先级和实际嵌套，不以所有 IRQ 同级代替分析。结合当前 map 确认向量、handler、调用函数、常量和编译辅助函数；把入口放 SRAM 不等于整条快速链不受 Flash stall。

IRQ 闭环为：外设源使能 → NVIC → 实际向量 → 链接 handler → driver → 事件/快照 → 前台消费者。weak 声明只是候选默认入口；若当前目标确实缺实现且中断可达，再按挂死/数据丢失等后果分级。

## 4. CBC、预充和复位

CBC 分开审触发来源、硬件逐周期动作、软件计数/积分、锁止、扣分和恢复资格。不能只测计数达阈值会停，还要测停后旧事件、旧候选或同轮任务不会重开。若 C300 合同规定 ISR 只关断、前台凭新候选恢复，就核查 ISR 未修改库 Duty/恢复 MOE，且停波和首恢复周期的积分语义正确；不要把此具体机制强加给其他产品。

普通预充与 Demo 分别追请求资格、停波、等待、新样本、压差/单向条件、合闸、稳定/反馈、超时与失败动作。复用公共操作不等于共用全部资格条件。“停波后”“等待后”的资格须用满足该时间关系的新样本；STOP/保护/维护能在执行前撤销待合闸请求。

GPIO 锁存或引脚读回仅证明命令/引脚，不能宣称机械触点已吸合。实际有辅助触点或其他经过定义的反馈时，核查该反馈来源、阈值和有效条件。

复位覆盖参数切换、采样失败、fault、OTA 等实际入口：

- 软件可控复位前按硬件合同停波、阻止新命令并处理功率继电器，核对中断重入/超时能否绕过。
- 独立看门狗/掉电不能假定会执行软件清理；核实定时器、引脚、外部驱动默认态与供电关系。
- BL→APP 与重新上电准入重新检查有效配置、样本、故障和输出默认态。

缺电路/数据手册/当前波形时列具体缺口，不由 Duty=0 推断重启无脉冲，也不由某个 reset API 推断 PWM 必然钉高。

## 5. 反例与实测边界

按改动风险选择必要验证：首个危险周期故障、read/arm 间插入 IRQ、计算到提交间新 fault、停止/维护后旧候选、连续/间歇 CBC、预充等待后的新样本、软件与看门狗复位。

Host 可以验证状态转移和注入顺序，目标构建可验证实际符号/链接，只有板上条件能证明真实极性、NVIC/ADC 时间、关断延迟、继电器反馈及负载下的波形。记录预期、实际、覆盖条件和未执行项；“测试了”不等于测试通过，更不等于 BOARD_PASS。
