# 采样、时间与状态

在 ADC/校准/滤波/功率、时间累计、模式和缓存、生命周期、WDT 或实时预算审查时读取。先识别采样事件、前台服务、控制更新和物理输出各自的时点，不把一次函数调用等同于一次新测量或一毫秒。

1. 一致快照与校准

## 1. 一致快照与校准

对关键测量列 `原码来源 | 单位 | seq | captured_at | 有效位 | 校准版本/条件 | 统计窗口 | consumer`。不是每个工程都必须新增所有字段，但必须有证据证明需要的一致性与时效语义。

- 驱动搬运和应用 sample 的发布边界清楚；DMA/ISR 不覆盖正在消费的缓冲。
- seq、采样时间、有效性与对应数据一起交接；重新读取旧快照不能刷新采集时间或序号。
- 电压、电流、功率、极值、平均值、有效样本数来自相容窗口及校准条件。需要跨窗口使用时明确模型，不能仍声称同一时刻/窗口。
- 复采替换电流后，检查功率是否按匹配电压重算，极值/计数是否重新建立或失效。不能只改一个字段保留旧派生量。
- 按当前 MCU 验证数据宽度、结构体撕裂、volatile 与原子读改写；使用快照、短临界区、代次或已有交接机制，避免引入无必要并发框架。
- 零点/标定由 sample 所属实现负责，启动/恢复/显式校准流程调用；采样例程不因拆模块而每次重新校准。
- 换平台、校准、滤波条件、配置变化后，定义旧统计窗口、历史功率、候选、缓存和累计状态何时失效/保留；默认清空全部历史也可能改变产品行为。

Safety snapshot 同样要有一致代次。若一拍 protection 执行两次或 ISR 使 epoch 改变，第二次后的 fault mask、disposition、unsafe、pending 等被共同消费的事实应整体更新，或证明原子/版本校验机制等价；不强制新增某个特定 C struct。

最终提交有意再读瞬时硬件可以合法，但说明它是新的安全复核、是否使当前批准失效、如何避免把新旧事实拼成一个看似一致的决定。

## 2. 时间、样本数与积分

| 条件 | 正确计量依据 | 重点反例 |
|---|---|---|
| 超时、冷却、充电时长、上报周期 | 单调时钟或真实 elapsed，定义回绕/暂停范围 | 漏 20 次服务却只加 1ms；补跑循环伪造流逝 |
| 连续证据、滤波、稳定窗口 | 新且有效样本数量，必要时同时限制时间跨度 | 重复 seq 被算成多个样本；大量积压后同轮补齐连续资格 |
| 容量/能量 | 有效电流/功率 × 明确时间区间 | 名义周期造成欠计；无限沿用旧测量造成过计 |
| 调试上报 | 实际时点与带宽预算 | 延迟后大量补发旧帧堵住控制 |

使用 `now - then` 时核实整数宽度、符号、最大间隔、时钟回绕和停止行为；不能仅见无符号减法就宣布任意长间隔正确。系统 tick 的 bool/counter 选择应与“只做一次当前服务”或“必须保留事件数量”的合同匹配。

漏服务不补造 ADC 样本。若只需最新值可合并过期处理，但超时应按真实时长；若必须统计每个事件，需有容量、溢出和消费规则。时间超期与样本不足是不同条件，不以一次调用同时假装满足两者。

计量审查需写清：

1. 用哪一时刻/区间的电流或功率代表积分区间。
2. 重复 seq 时是否允许继续积分、允许多久、依据是什么。
3. 缺样、stale、Flash 暂停、采样恢复、时间跳变及长间隔的处理。
4. fixed-point/float 单位、溢出/饱和、舍入误差和保存事务。

固定周期在受证明的硬实时路径可成立；当前没有时序证据时不能把“名义 1ms”当已验证实际间隔。

## 3. 生命周期、模式与缓存

列每条实际 transition 的触发、Owner、状态写点、库 reset、候选失效、继电器请求和 PWM 动作。区分“本拍不输出”和“会话已结束”；例如 Relay 瞬态是否需要 debounce，必须与 charge/库 reset 的合同一致。

相同 transition 被多个层重复解释时找根因；有幂等性仍可能是结构问题，但等级取决于实际影响。不要机械要求每条 STOP 只能出现一个停止函数：不同时间屏障或安全硬停与前台归档可能合法。

模式审查从入口到真实写点：初始化、运行、切换、退出、持久化与清理。两个薄入口都转到 `shared(mode)` 不证明已分离，也不证明必然不合格；看专属状态是否在合适 Owner 中，公共数学是否被合理复用。C300 的普通和 Demo 可以在 charge 内表达，无须新增应用模块。

同一个采样/控制事件内列 preview、阶段推进、正式更新、候选、资格和批准所用输入。临时 scratch 内含正式状态指针时，沿别名检查写入。若 preview 和正式 update 都推进滤波/积分/状态，核对是否重复消费以及资格/诊断是否混用了前后阶段。

对缓存建立 `键 | 被缓存字段 | 外部依赖 | 失效/收紧条件`：

- seq 相同但有效位、采集时刻、模式、配置、校准或限制来源改变，结果和资格是否仍可复用。
- min/cap 数值相同不等于来源或停机语义相同；合法零、禁用和无效须分别理解。
- 重复测量下按合同只保持/收紧，不意外再次搜索、积分或推进连续证据。
- 缓存电压/温度/模式相关参数时有明确刷新策略；仅随配置变化的计算可评估在原子配置提交时预计算。
- 诊断/shadow 标志不得未经需求进入生产 inhibit/恢复；观测路径的副作用也必须查。

## 4. WDT 进展与 deadline

WDT 是有限时间内的健康决策，不能因 main 转圈或 CONTROL 函数返回就永远喂狗。核查关键生产者（如 ADC seq）和控制处理（消费/完成代次）的进展窗口，以及卡住时谁停止喂狗。

不要求每一圈都出现所有新样本；允许窗口内独立票据或等价机制。必须能区分合法低频任务、尚未到期、确实停滞和被重复使用的旧票据。

启动、校准、维护、Flash 等可有明确预算和专门策略，审进入条件、预算来源、超时安全路径、退出后新鲜数据与恢复资格。不能成为无限绕过健康检查的入口，也不能用已停走的同一时间源证明自己仍健康。

活性与 deadline 分开：即使 ADC/control 都最终推进，1ms deadline 仍可能被 tick 合并、无 FPU 浮点、sqrtf、Flash stall、阻塞 printf、通信积压或长关中断破坏。只出现上述调用是风险线索，不等于已经超时；用当前目标配置、map、WCET/最大服务间隔和负载测量收口。

主循环顺序应清楚：取得时间/样本，按约定运行保护/charge/交互等任务，最终输出按当时条件复核。拆文件本身不要求引入 RTOS、线程或新的调度层。

## 5. 验证矩阵

根据本批实际变化选择反例：重复旧 seq、复采一个通道、换校准/平台、长服务延迟、tick 回绕/停止、Flash 暂停、mode 切换、preview 别名、限值同值不同来源，以及 ADC 或控制单独停滞。

同时看结果与过程：派生量是否同源、旧样本是否被伪造新鲜、timeout 是否按真实时长、连续证据是否确实新增、积分与缺样策略是否一致、WDT 是否在规定预算内停止喂狗。Host 可证状态/算术合同，真实采样时刻、模拟波形和目标最坏耗时须另列板级证据。
