# 采样、时间与状态

在测量、校准、滤波、计量、模式、缓存、生命周期、WDT 或实时预算审查时读取。区分采集、服务、计算、提交和物理动作各自时点；一次函数调用不自动等于一次新测量或固定时长。字段名、存储形式和调度模型由当前工程决定。

## 1. 数据一致性与校准

对关键数据记录来源、单位、身份、采集时点、有效性、校准条件、统计区间和消费者。只需要语义可核实，不要求每项各新增一个成员或对象。

- 数据搬运、发布与消费边界清楚，生产方不能覆盖仍在消费的数据。
- 标识、时间和有效性应对应同一数据；重新读取旧快照不能伪造新采集。
- 组合量、极值、平均值及有效计数的输入区间和校准条件相容；跨区间估算要有明确模型。
- 替换部分输入后，检查受影响派生量、统计与缓存是否重算、保留或失效；不能只改原量仍声称旧派生量同源。
- 按目标核对数据宽度、结构撕裂、原子读改写和内存可见性，使用已有适合机制，不为假设的并发增加框架。
- 校准执行时机、准入条件、更新和失效规则符合当前需求。启动校准、显式校准和在线校准都可成立，不能把一种方案规定成通用要求。
- 模式、配置、校准或滤波变化后，明确历史、候选、缓存和累计量的保留范围；默认清空一切也可能改变功能。

故障、许可及其他共同参与决策的状态同样需要一致性。多次评估或异步更新后，检查消费者是否组合了不相容的新旧结果；完整刷新、原子交接或版本校验等实现按工程选择。

最终动作有意读取瞬时硬件可以合理；说明它是新的复核、何时使旧批准失效，不能将其伪装成原快照的一部分。

## 2. 时间、事件次数与积分

| 条件类别 | 核对依据 | 典型反例 |
|---|---|---|
| 超时、冷却、运行时长、上报周期 | 实际时长，含回绕、暂停和允许误差 | 漏多次服务却只累计一次名义周期 |
| 连续证据、滤波或稳定条件 | 新有效事件/样本数量，必要时限制跨度 | 重复旧值被算成多个新样本；一次补跑伪造连续资格 |
| 容量、能量或其他积分 | 有效测量代表的明确区间与缺样策略 | 依赖名义调用周期欠计，或无限保持旧值过计 |
| 通信/日志调度 | 时点、丢弃/合并策略与预算 | 延迟后集中补发旧数据挤占关键工作 |

时间差计算需核对类型宽度、符号、最大间隔、回绕及停止行为。时间源、节拍标记或计数器的选择，应符合保留事件数量还是只处理当前状态的需求；不强制某种数据类型或固定周期。

漏服务不能补造真实测量。只需最新状态时可合并过期处理；必须统计每个事件时要有容量、溢出和消费规则。超时与样本不足是不同条件，不能用补跑循环同时假装满足。

计量需说明：

1. 哪个时点或区间的测量代表积分区间。
2. 重复数据是否允许继续累计、允许多久、依据是什么。
3. 缺样、暂停、恢复、时间跳变和长间隔的处理。
4. 单位、运算宽度、溢出/饱和、舍入和保存语义。

固定周期积分在具有对应保证与证据时可成立。没有当前时序证据时，名义调度频率不能当实际周期证明。

## 3. 生命周期、模式与缓存

对实际状态迁移列触发、决定者、状态修改、计算重置、候选失效和硬件动作。暂时禁止动作与结束整个业务会话可能不同，需按本项目合同解释。

同一迁移被多个层独立解释时查分叉；幂等不能替代职责判断。不同时间屏障、硬停和后续归档可以合理，不强制每次迁移只能调用一次某种操作。

模式审查覆盖初始化、运行、切换、退出、保存和清理。多个入口共享实现既不证明职责已分离，也不证明有问题；看专属状态与公共计算的实际归属，不要求为每个模式新建文件。

对预览、阶段推进、正式更新及批准的输入与副作用逐步取证。临时对象仍可能通过指针引用正式状态；同一事件可能被重复消费；资格与结果也可能分别使用阶段切换前后的条件。

缓存需关联被缓存结果、外部依赖、有效期和失效条件：

- 输入身份相同但有效性、时间、模式、配置或校准改变时，结果是否仍可复用。
- 最终数值相同但限制来源、合法性或动作语义不同，是否错误命中。
- 重复输入下是否按合同保持、收紧或重算，是否意外再次推进状态。
- 预计算是否有稳定依据，配置切换能否同步更新全部依赖。
- 诊断/对照是否未经批准进入正式许可或恢复路径。

## 4. WDT 与实时预算

若看门狗承担控制健康监测，应按规定窗口核对关键产生者与消费者是否推进，及失败时谁停止刷新。循环运行或函数返回不能单独证明所有受监测工作健康。

健康策略需区分正常低频、尚未到期、确实停滞和重复旧凭据。不要求每次循环所有任务都产生新数据，也不规定必须采用固定数量的票据。

启动、校准、维护等阶段可有专门预算和策略；核对进入、超时、退出及恢复资格，避免无限豁免。已停走的同一时间源不能证明自身正常。

活性与截止时间分开。最终能完成不证明按时完成；检查调度合并、运算成本、存储忙、日志阻塞、通信积压和临界区等适用因素。调用名或数据类型只是线索，结论应依据当前目标配置、最坏耗时或负载测量。

审查现有串行、RTOS、事件驱动或混合调度中的顺序、抢占和依赖；不因拆文件增加线程，也不为了满足原则把已有并发模型改成前台串行。

## 5. 验证选择

按改动选择重复旧数据、部分复采、校准/模式变化、长延迟、时钟回绕/停止、存储暂停、预览别名、同值不同来源、关键生产者或消费者单独停滞等场景。

同时观察结果与过程：数据是否相容、时间是否真实、连续证据是否新增、缺样处理是否符合约定、看门狗是否按预算响应。主机可证部分状态和算术合同，真实采样时刻与目标最坏耗时须另取证。
