# Product Doc

版本：1.0.0。**说明这版产品做什么、什么时候做、参数是多少、做不到或还没确认什么。**

先读[文档组合与讲解方式](references/document-set.md)、[参数与证据规则](references/parameter-evidence.md)、[多格式与验收](references/quality-and-delivery.md)。需要逐函数学代码时用`code-study`；产品文档不能把函数教材换个封面。

## 1. 锁定当前实现

确认当前源码、版本/HEAD/dirty、构建变体、有效编译宏、硬件版本与已提供的测试报告。以用户指定输入为准；历史学习书只帮助定位，必须核对同一源码摘要。资料冲突单列，不悄悄填补。缺Boot/SDK/构建选项时限定可确认范围，不臆造最新实现。

默认写`docs/product-doc/<baseline-id>/`；不改产品源码、参数或安全策略，不顺手跑烧录、固件编译、未知脚本或部署。用户有足够输入就执行，不反复索取确认。只对影响结论的无法确定项询问，其余可先产出并标未知。

## 2. 先规划产品文档，不固定套七册

按[文档组合](references/document-set.md)选择专题。中型嵌入式产品通常分成：产品与主要参数；上电/启动/执行器；业务阶段与档案；调节与输出；保护停止恢复；通信设置保存升级；参数口径与验收。简单产品合并，不适用主题删除，有新功能补专题。不要硬塞电池/MPPT，也不复制前一项目的12档、102项、7册和48页。

先形成实际功能清单、当前启用/关闭/条件启用/未提供表、参数台账和矛盾表，再写正文。产品定位要来自已有要求或源码功能，不能从项目名推测认证、环境指标和销售承诺。

## 3. 逐功能追运行逻辑与参数

沿入口→采样/数据资格→开始条件→准备→正常工作→异常停止→恢复→设置/保存→升级追踪。每个功能按[运行逻辑模板](assets/templates/module-logic.md)给进入条件、具体动作、参与数据、判断式和时间、输出、失败去向和用户可见现象；图上直接写实际参数，不只画状态名。

所有关键值既查定义，也查使用表达式和其他限制。分清电压/电流测在哪里、平均/峰值/原始码、输入/输出功率、目标/预算/保护/物理额定、连续时长/累计次数、计时起点、模式/档案及编译条件。把临时估算与实际测量分开。

回答“多少电压满功率”必须把所有有效限制共同求交，给必要条件和推导，不能拿某条降功率公式的拐点作满功率承诺。没有效率实测就不能把输入功率等同输出功率；没有独立电流采样不能说成精密恒流。详见参数规则。

故障表包含触发比较符、数据类型、确认时间、立即动作、继电器/执行器处理、锁定、恢复比较符和时间、自动/人工恢复。命令受理、内存生效和Flash保存分开。不能把“控制脚已输出”写成“触点实测已接通”。

## 4. 写得像产品说明，仍可追到代码

正文用口语解释动作，不用“退避、合闸、Owner、DTO”代替过程；代码标识放在依据和参数表，不让产品读者先读完整函数。模块正文给正常、未满足、超时/故障和再次开始场景。参数较多时正文写关键值，完整台账独立，但关键结论的适用条件不能藏到附录。

来源分类固定为SOURCE_CONFIG、ACTIVE_LOGIC、DERIVED、MEASURED、UNKNOWN，并在正文翻译成人话。源码注释与活动表达式冲突并列记录；没有信息的效率、精度、温升、EMC、IP和绝对电气额定必须明确待确认。

## 5. 生成和交叉检查

Markdown是唯一正文源，CSV是结构化参数来源；同一次构建导出HTML和用户要求的可编辑Word。完整产品包默认规划MD+CSV+SVG/DOT+HTML；Word在要求“可编辑/正式评审/合订本”或本次明确要求时生成。不能把格式导出当成已经做过产品测试。

使用[台账模板](assets/templates/parameters.csv)、[保护表](assets/templates/protection.csv)、[待执行验收表](assets/templates/acceptance.csv)。先以真实文件构建`verification/source_manifest.json`，再核对：

```bash
python "$SKILL_DIR/scripts/product_doc_check.py" --book "$BOOK" --source-root "$SOURCE_ROOT"
```

辅助脚本只核对表结构、证据路径/范围/哈希、推导字段、章节/图/链接及HTML存在，不理解业务公式、不生成成品、不自动宣布语义或实机PASS。返回0只表示所列机械检查通过；报告由命令stdout保存，缺资料就如实FAIL/未运行。

逐册对照当前源码复审；特别核对正文、图、台账、档案表和导出格式的数值及条件一致。数据量、章节数和页数从成品统计。Word必须渲染后逐页看表格、分页和图；HTML必须file://打开检查搜索、跳转、源码引用及图放大。不能声称视觉通过而只读过XML。

## 6. 交付和继续更新

入口说明版本依据、适用范围、各专题作用和限制；提供变更清单、实际检查记录、待执行验收，不自动勾通过。默认就地生成目录，不自动归档或推送；用户明确要求聊天附件/ZIP时交付完整包。用户授权提交也只限本次范围，不上传未授权的固件、客户文档或测试数据到公共skill仓库。

更新时比较当前源码与旧台账，逐项追定义和使用处变化；重建受影响正文/图/档案表/HTML/Word并重新检查。不只把页眉版本号换掉。与代码学习书同源但目录独立，不覆盖`Application`或`code-study`。
