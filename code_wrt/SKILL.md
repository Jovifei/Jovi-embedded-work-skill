# Code WRT

**Version: V0.4.4**

以本次需求、当前工程和可核实证据完成嵌入式代码修改。保留合理实现与已确认合同，用必要的职责、清楚的接口和相称的验证解决问题。

**本技能规定判断和执行方法，不预设项目的模块数量、目录、文件或函数名称、调度模型、芯片、算法库、阈值及状态布局。** 具体实现由当前需求和工程证据确定。示例中的名称和结构只说明推理，不是默认方案、迁移目标或验收条件。

## 1. 明确范围，沿用已有授权

1. 区分方案、只读审核、注释整理和代码实施；先读指定源码、项目规则、构建入口及必要调用链。保留已有工作区和暂存修改。
2. 分别标识原工程/在役基线、参考实现、合并双方和当前修改版等实际相关来源。记录源码身份、目标配置、依赖和验证条件；未提交内容用 hash 绑定证据。
3. 列出必须保留的行为、参数、接口和外部兼容要求，以及已允许改变的内容。旧计划和历史问题均对照当前源码重查。
4. 已授权阶段继续执行，不因模板、辅助技能或每个小批次重复询问。未确定的产品行为、范围扩大或不可替代的关键取舍才提出具体问题。
5. 已确认且在授权范围内的 BUG 应修复。仅授权等价整理时，单列行为修复及反例，先完成能证明等价的部分。
6. 吸收参考实现前说明改善、适用前提、兼容影响和验证方法；参考工程的名称、模块划分、数值和时序不自动成为本项目要求。
7. 提交、推送、合并和部署按本会话已有的仓库与操作授权执行；不擅自扩大范围，也不反复索要已有授权。

按实际变化分别登记：

| 类型 | 要求 | 证据重点 |
|---|---|---|
| 结构整理 | 保持约定的可观察行为和调用合同 | 职责映射、调用时点、初始化/异步入口、构建引用 |
| BUG 修复 | 触发条件、因果链和最小修复明确 | 修复前反例、修复后结果、相邻路径 |
| 已批准功能 | 新行为及兼容影响明确 | 正常、边界、失败、恢复、旧配置和部署 |
| 性能/空间优化 | 先确认瓶颈，再选局部方案 | 同条件前后资源、耗时与功能对照 |

启动、执行顺序、限幅、恢复或持久化语义改变，都不能只登记为“结构整理”。

| 修改范围 | 执行深度 |

| 实时、并发、执行器、存储或升级 | 增加相应时序、失败恢复、目标和必要实测项目 |

## 3. 明确职责，不预设实现形状

- 每个关键事实、可变状态和决策都有明确的维护责任、允许写者与消费方式；复制与缓存必须有同步或失效合同。
- 职责不是文件数量。沿用清楚可工作的实现；新增模块、封装或数据类型应有独立责任、复用、兼容或验证收益。
- 按实际裸机循环、RTOS、事件驱动或其他运行模型判断调用顺序和并发。不能仅凭“任务”名称禁止调用，也不能未经分析把并发改成串行。
- 调用与数据边界体现真实权限：调用者不绕过必要校验，不任意修改别处私有状态。共享流程可由现有编排、普通接口或事件完成，不默认增加协调层。
- 在需要硬件可移植性时，把芯片访问和业务规则隔离在明确接口两侧；具体文件位置和接口方式依项目决定，不能把搬目录当作完成隔离。
- 接口按真实需求选择标量、现有只读快照或稳定对象，不机械增加传输对象、公共头或转发函数。既有外部 ABI 按保留或明确迁移合同处理。
- 观测功能与控制动作的权限明确；已批准的诊断控制可有正式接口，不能借调试入口绕过正常运行约束。

跨边界改动只填写必要合同：

| 职责/维护者 | 实际调用关系 | 上下文与时机 | 数据、单位、有效期 | 副作用与失败结果 |
|---|---|---|---|---|
| 据当前工程填写 | 不预设函数名 | 据实际运行模型 | 据真实消费者 | 明确允许写入者 |

## 4. 保持接口、数据与状态含义一致

1. 改接口时列完整旧/新签名、输入输出、单位、值域、生命周期、执行上下文、失败语义和副作用；同步声明、定义、调用、回调及外部消费者。
2. 状态、输入快照、命令、事件和产物按真实用途命名，不能由变量名猜并发或强制改成固定名称。
3. 区分建议值、获准动作、已提交命令和实际生效结果；只在证据支持时宣称物理状态。
4. 合法零、未启用、无效及停止请求的含义由合同定义。外部编码保持兼容，内部表达可在授权下澄清。
5. 对初始化、切换、停止、故障和恢复，明确保留、重置和失效的状态；必要的历史、积分、序号及事务记忆不能因不导出而删除。
6. 约定只读的预览不能间接修改正式状态。实际写入与声明不符时按行为问题处理，不能隐藏在等价整理中。
7. 缓存和预计算基于真实收益；列完整依赖和更新失效时点，相同序号或相同最终值不自动证明可复用。
8. 数值等价核对整数提升、中间宽度、符号、计算顺序、截断、饱和及回绕；改变算法或表示方式另列范围。

## 5. 保持运行上下文和安全仲裁

- 普通控制调用不必转成中断。异步事实通过项目适用的回调、事件、缓冲或快照交接，明确真实执行上下文及生命周期。
- 修改异步路径时追到硬件或调度入口、实际执行处理、数据交接与消费者，不能仅凭声明或成功链接判定已接通。
- 按最坏执行时间、优先级、可阻塞性和调用约束安排工作。严格实时路径禁止无界等待和不适用的阻塞操作；算法放置不能仅凭名称决定。
- 正常执行器动作有明确的最终许可与提交责任；多个调用入口必须遵守一致仲裁，不能用旧请求覆盖较新的否决。实现不限定具体模块名称或调度顺序。
- 工程要求立即响应的硬件/中断关断通道应保留其时限，不为集中代码延迟到较慢任务。后续状态归档和重新使能按明确恢复合同执行。
- 临界区、锁、原子操作或消息交接按实际并发选择；中断屏蔽恢复原状态，范围有界。不能用 volatile 代替一致性，也不为不存在的并发加锁。
- 不同时点的复核可能保护不同竞争窗口；删除前证明用途等价，保留有意义的失败撤回和过期请求失效机制。

## 6. 保持时间、持久化与通信合同

- 数据按使用需求可追溯其来源、单位、采集时刻及有效性；重复消费不能冒充新采集。有关联的统计量保持相容来源。
- 超时使用真实时间，连续证据使用符合条件的新观测，积分使用明确有效跨度与缺样策略；不把服务次数当作必然经过的时间。
- 健康监测依据规定窗口内的必要进展。合法启动或维护例外有预算，不能用已停止的监测时源证明系统健康。
- 配置和持久化以完整有效版本生效；失败不留下半套状态，不推进依赖其成功的后续破坏性操作。
- 通信检查容量、字段关系、完整消息及缓冲生命周期；区分命令接受、生效、排队、实际发送和对端确认。
- 升级与部署变更覆盖兼容组合、首次安装、失败恢复和回退；共享格式保持一致，不能只验证一条成功路径。

## 7. 小批实施并验证最终内容

1. **写前**：固定范围、来源、保留合同和变化类型，读相关参考，确定可暴露实际风险的验证方法。
2. **实施**：完成授权小批，更新实际消费者、构建引用和必要注释；不靠恢复退役接口迎合过时夹具。
3. **合并/写后**：按最终内容核对接口、状态、副作用、并发和构建成员。冲突按语义解决，不盲选一方；父分支通过不自动传给合并结果。
4. **验证**：按风险采用静态、Host、目标构建或实测；不为低影响改动堆无意义测试。缺实板等条件时继续可做工作，并保留相应放行条件。
5. **交付**：证据绑定最终内容和工具配置，分别标通过、失败、未执行、受阻或限制；回退只处理本批变化。

按项目约定更新受影响的版本、说明和学习资料。技能版本与产品版本分开；纯文档不自行升固件版本。已有知识库同步约定要落实，未完成不得声称成功。

## 8. 完成报告

报告本批目标、实际变化、必要接口/职责说明、源码身份、验证结果、未完成项及其条件。小改用短表；较大批次可用 [记录模板](references/scope-and-verification.md#批次记录模板)，按实际裁剪。

Host、目标构建、CI、架构审查和实板各自只证明覆盖范围。实现完成不等于所有硬件或部署验收完成；旧日志、脚本退出 0 和能编译均不能代替本版完整证据。
