## 按实际函数体命名

改名前读完整函数体、返回值、out 参数、全部调用及副作用。名字覆盖主要动作、对象与产物；职责过多时，只在授权范围拆分，否则记录问题，不用更漂亮的名字掩盖。

| 词义 | 合同 |
|---|---|
| `init` | 对象/硬件初始化，不暗中执行运行策略 |
| `start/stop/reset_*` | 明确生命周期和重置范围 |
| `step/update` | 一次状态/控制推进；调用者决定调度时机 |
| `dispatch` | 路径选择；不冒充计算或硬件提交 |
| `evaluate/calculate/select/clamp` | 写清产物及是否修改状态；选择、计算、限幅各按实际命名 |
| `service` | 消费本 Owner 的 pending/deferred work，不收纳全部业务 |
| `apply/commit` | 说明应用到内部状态还是硬件；commit 明确提交完成点 |
| `get/read` | 默认只读，read-clear 或消费事件须显式声明 |
| `set/write/request` | Owner 提供明确的设置/命令语义，不作为任意 peer mutation 入口 |
| `is_*/*_ok/*_valid` | 纯判断；会更新时基、锁存、积分的函数不能伪装判断 |

不同问题不要收成同一个 `ok`。样本资格、电池电压窗、温度启动资格、输出空闲分别保留对象词。返回功率/电压/比较计数的函数体现单位或明确结果角色。

自有符号遵守当前项目 snake_case 和公开/私有前缀；保留 SDK/CMSIS、startup IRQ、外部回调、协议和供应商 ABI 名称。公开前缀若保留给 public API，私有 `static` 不使用它；不机械重命名可工作驱动来满足个人偏好。

已有模块词只替换需要的部分，不叠成 `charge_stage_stage_*`。私有 helper 用清晰短名；纯数学函数不必叠加模块前缀。硬件动作保留在名字中，例如 `output_pwm_apply`。

同后缀并非重复职责。`control_step` 与 `duty_controller_step` 可以各推进不同状态；先查真实作用再改名，不能只为避免两个 step 改成不完整名称。

## 分层命名示例

下表仅供**已采用自有 MPPT 分层并确认命名合同的工程**，不要求当前 C300 拆出搜索/算法模块，不改原闭源库符号。

| 对象 | 示例 | 注意 |
|---|---|---|
| 公开应用入口 | `app_mppt_evaluate_candidate_duty()` | 明确候选产物，不称实际输出 |
| 搜索入口 | `mppt_search_step()` | 表示搜索推进，不代表完整控制器 |
| 算法编排 | `mppt_algo_control_step()` | 若仅分发，可按实际改为 dispatch |
| 功率到候选控制 | `mppt_algo_duty_controller_step()` | 可能包含前馈、PI、限压/限流，不能漏掉职责 |
| 搜索私有 helper | `update_vref_step()`、`process_search_average_window()` | 暂停、启动与统计副作用仍应对应名字 |
| 数学 helper | `clamp_float_range()`、`calculate_power_mw()` | 纯计算不伪装状态推进 |
| 私有类型 | `mppt_search_ctx_t`、`mppt_algo_input_t` | 归真实 Owner，不假装 public API |
| Demo 专属量 | `demo_startup_duty_floor_permille` | 不让普通档误用 Demo 策略 |
| 参考电压 | `vref_mv`、`vref_upper_mv` | 不把不同目标和边界统称 target |

层级、Owner、动作和对象都由源码确认；函数名带 `step` 不代表命名错误。`floor`、理论 `boundary`、批准 `max`、启动限制与永久限制分别解释。

## 参数与输出语义

优先明确的单位和角色，如 `now_ms`、`timeout_ms`、`pv_mv`、`pv_i_ma`、`power_limit_mw`、`frame_len`、`channel_count`、`profile_id`。含糊 `value/data/flag/temp/mode/status` 在跨模块接口需补对象或单位；局部短名按可读性，不机械拉长。

| 名称 | 事实 |
|---|---|
| `candidate_*` | 策略/算法提出的候选 |
| `approved_*` | 已通过相应资格/限制，但不等于硬件生效 |
| `committed_*` | 已交给执行器/驱动的设定 |
| `hardware_*` | 有硬件事实支持的实际生效状态 |
| `relay_request_on` | 请求 |
| `relay_odr_on` | GPIO 锁存读回 |
| `relay_contact_closed` | 仅真实触点反馈支持时使用 |

`drv_pwm_get_duty()` 若返回设定，不能把它命名成候选或实测占空比。CCR/周期比是否代表真实导通取决于极性、模式、死区和更新；名称和单位跟随实际硬件合同。

`last_control_ms` 可能是控制处理点，不必然是积分端点，结合 `control_dt_ms` 和实际更新说明。功率请求、阶段允许、MOS 降额前值、最终批准和限幅来源分别保留，不靠改名改变数据含义。

## 结构体与目标 ABI

授权涉及结构体整理且布局可变时，可按相同声明类型集中成员，同类型保持原相对/用途顺序；`float`、`uint32_t`、`int32_t`、`uint16_t`、`uint8_t`、`bool` 分别处理，不能因同宽把 bool 和 uint8_t 合组。组序优先项目约定，其次考虑目标自然对齐。

重排前核对：

- 所有位置式/指定式初始化器及复合字面量，确保值仍落到原语义字段。
- `sizeof/offsetof`、raw memcpy、序列化、Flash/协议/DMA/寄存器布局。
- packed、bitfield、汇编、回调/库 ABI、对齐、编译器和处理器选项。
- 测试/工具/二进制消费者是否把字段顺序或对象大小写死。

外部固定布局、供应商库结构和 ABI 保持原样并记录例外；不通过重定义类型、改 packed、私写内部字段绕过兼容性。可改内部结构保持语义和类型，必要时更新初始化器及布局检查。

用目标编译器/ABI 验证大小、对齐和偏移；Host 结果不能直接代表目标。没有目标证明不宣称固定 RAM 节省。不为字段分组新增嵌套 struct/头文件，也不把用户说的成员顺序扩大成函数形参改序。

## 头文件和配置

优先真正 Owner 的现有头或 `.c` 私有定义。新增公共头应有真实独立合同、多个合理消费者、打断依赖环或外部生成格式依据；不为一个宏/DTO/一行 wrapper 单建文件。

| 内容 | 放置原则 |
|---|---|
| 产品共用参数 | 现有产品配置 Owner；不强制新建 `app_config.h` |
| 模块公共类型/API | 该模块已有头 |
| 私有状态/调参/helper | 本 `.c` 或必要私有头 |
| MCU/硬件配置 | 驱动/板级映射 |
| APP/BL 共用格式 | 真正共享定义；不收杂散业务全局量 |

少文件不能变成万能 `main.h`。也不能为概念分类强制新建 `mppt_config.h` 等配置文件。

使用跨模块符号时直接 include 真实 Owner，避免碰巧的传递可见性。安全宏确认每个消费编译单元的实际值，必要时显式 definedness 检查，防止未定义按 0 静默关保护。用户已明确移除某项 `#error` 时不以 assert/typedef 绕回；仍核对直接依赖、实际宏值和运行门。

## 注释与迁移完成

按项目现有注释、大括号和分节格式。无约定时可用 `.c` 的 `/* 标题 */`、`.h` 的分节注释；这些不是重排全工程的理由。

公开入口、复杂私有函数和有安全/状态副作用的函数说明：功能、调用者/上下文、输入单位与前提、结果、修改状态/硬件、失败处理和必要时间要求。行内注释解释为何需要资格/顺序/边界，不逐行翻译赋值。用户要求逐行时按指定粒度完成。

Init/SysClk 按“配置了什么”分节；宏写用途、单位/枚举和当前值含义。注释不能把 pending 写成完成、GPIO 镜像写成机械反馈、初始化写成恢复或候选写成实测。

改名完成时核对活动定义/声明/caller/回调/初始化器、测试/decoder、当前文档和工程；明确历史与外部 ABI 例外。按受影响范围编译/静态检查，未运行项如实标记。仅注释范围发现行为缺陷时记录缺陷，不悄悄修改代码。
