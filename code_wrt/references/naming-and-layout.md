# 命名、布局与注释

处理命名、头文件、结构布局和注释时读取。项目现行合同优先；这里的符号只在明确标注的示例中说明含义，不要求创建或采用它们。

## 命名依据

改名前读取函数完整实现、调用者、结果和副作用。名字应表达实际主要动作、对象与产物；职责过多时，仅在授权范围拆分，不用新名字掩盖问题。

初始化、状态推进、选择、计算、提交、只读观察和消费事件是不同语义。既有命名约定可以不同，但调用者不应被名字误导；有状态写入的查询尤其要说明真实行为。

自有符号沿用当前项目风格及公开/私有规则；供应商、向量、外部回调、协议、存储和库 ABI 名称按兼容合同保留。没有命名约定时选择清楚、一致的局部方案，不先替全工程制定新前缀。

同一个后缀可以用于不同职责。不要只为消除文字重复而省略重要行为，也不要为“完整”把所有调用动作拼进一个超长名称。

**命名示例，仅说明判断，不规定 API：** 一个只提交传感器读取请求的接口，名称应体现“请求”；只有取得并验证了新结果的接口，才能声称“已读取”。具体函数叫什么、是否需要两个接口，由现有调用合同决定。

## 参数与结果

参数和字段按真实角色、单位、来源和有效性表达；跨边界的含糊名称应结合调用者澄清，局部短名可按可读性保留。修改名称时保持数据来源和运算不变，除非另有行为修复授权。

区分候选、获准动作、已提交命令、驱动设定与物理结果，但不强制每层各有字段或类型。合同允许合并的阶段可以合并描述，不能虚构尚未观测的生效状态。

**状态示例，仅说明证据边界：** 写出继电器控制引脚与触点闭合不是同一事实。没有反馈传感器时，名称和注释只能表达可确认的命令或引脚状态，不能宣称已经确认机械动作。

时间字段说明记录的是采集、服务、提交还是积分端点。不同限制来源与不同计算阶段有实际消费者时应保留含义，不能靠改名混同。

## 结构布局与 ABI

授权涉及结构体整理时，先区分可调整的内部布局与外部固定布局。按项目约定或具体资源收益重排，不能仅凭“统一风格”跨模块改类型、成员顺序或函数参数顺序。

重排前核对：

- 位置式/指定式初始化及复合字面量，确保值仍属于原语义字段。
- sizeof、offsetof、原始内存复制、序列化及持久格式。
- 通信、DMA、寄存器、位域、压缩布局及汇编/库/回调 ABI。
- 测试、工具和其他二进制消费者的布局假设。

**布局示例，仅在工程已经采用该约定时适用：** 可以按声明类型分组并保留同组原顺序；但协议记录即使类型交错，也必须保持其已确定的字节布局。分组不是本技能要求所有工程采用的默认布局。

大小、对齐和偏移由目标编译器及选项验证。Host 结果不能直接代表目标；没有目标证据不宣称固定 RAM 收益。不为调整布局增加无必要的嵌套对象或头文件。

## 头文件与配置归属

将公共合同放在真实维护者的现有接口中，将私有细节留在实现或必要私有头。新增公共头应有稳定独立合同、合理消费者、依赖治理或外部格式需求。

产品共用参数、模块内部参数、硬件映射和跨镜像格式的责任不同；按实际消费者决定位置。不能把减少文件变成全局杂物头，也不能为每个概念建立一个配置文件。

依赖应明确稳定。核对真正的定义来源、公开重导出合同、构建宏及各消费编译单元的实际可见值；不能依赖偶然包含顺序使安全配置生效。

对缺省为零会改变保护的宏，按风险设置可验证的定义或配置检查。若用户已明确移除某项编译禁令，不以另一种写法恢复同一禁令；仍核对实际值和运行约束。

## 注释与迁移完成

沿用项目注释和格式。解释接口的功能、调用上下文、输入前提、输出、状态/硬件副作用、失败处理与时间要求；行内说明非显然原因。用户指定逐行粒度时按要求完成，但不复述标识符充数。

说明当前真实行为，区分实现意图、静态证明和实测结果。初始化、等待、恢复、排队、发送完成和对端收到不能互相替代。

纯注释整理保持可执行语义。格式或布局动作另核对授权、控制体、预处理、作用域和依赖；发现行为问题单列，不靠文字伪装已修复。

改名后核对活动定义、声明、调用、回调、测试、工具、文档和构建；历史快照和外部固定名字列明确例外。按影响执行检查，未运行项如实记录。
