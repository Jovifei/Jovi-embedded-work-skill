## 职责和调用方向

| 角色 | 负责 | 边界 |
|---|---|---|
| 驱动/板级实现 | 寄存器、SDK、引脚/通道、IRQ 事实、原码和硬件执行 | 不 include 充电业务头或解析应用 ctx |
| 数据处理 | 单位换算、校准、滤波、快照身份和有效性 | 不决定充电阶段或独立开启功率 |
| 业务/策略/算法 | 模式、阈值、约束、状态推进、候选 | 不越过输出复核或修改其他模块私有状态 |
| 正常功率输出 | 当前资格、首拍/斜率、功率继电器、最终提交 | 不重算电池策略或改库私有状态 |
| 调度 | 初始化、时间、任务顺序、系统健康 | 不吸收所有业务成为新万能模块 |
| 观察 | 只读快照、带宽预算、日志/诊断 | 不反向控制正常策略 |

把角色放入现有合适模块即可，内部函数能保持 `static` 就保持 `static`。不为每个角色建 Adapter、Service、Coordinator、Executor 文件，不为两个调用套转发链。

正常硬件命令经明确驱动 API 执行；异步事实由驱动 ISR 发布事件/快照，前台消费。紧急关断可在硬件/驱动 ISR 立即完成；前台正常功率提交保留最终审核。LED、串口、Flash 等按各自 Owner 调驱动，不经过功率 output。

顶层 task 由 main/既有调度者排序。普通跨模块函数可以是只读获取或窄语义请求，明确单向依赖、状态所有者和生效时点；不把所有普通调用强制变成事件或中断。互相写内部状态或循环策略依赖应先修边界，不能用 callback 掩盖。

对自有算法，充电阶段属于业务 Owner，不放入算法 controller 让算法管理全局会话。对供应商库，保持原接口/结构/ABI，不把自有分层模板强加到其对象。

## 接口选择与完整签名

先查真实数据需求。少量标量、既有只读快照或现有库结构足够时直接使用；新 DTO 只用于稳定且确有必要的边界。禁止巨型 ctx 泄漏整套上游状态，也禁止为了窄接口新建一批复制对象/包装头。

改接口时列出**完整旧签名和新签名**，包括返回类型、每个参数的类型/顺序/const、指针方向与 callback ABI；实际报告不可用 `...` 省略。并说明：

| 合同 | 需要核实 |
|---|---|
| Owner/Caller/Callee | 谁拥有状态，全部实际入口，允许的下游 |
| Timing | ISR/前台/任务/事件，频率、调用顺序、允许最长耗时 |
| 输入 | 来源、单位、值域、有效期、新鲜度、mode 与配置代次 |
| 输出 | 返回值与 out 的独立含义，候选/已提交，失败时是否写 out |
| 副作用 | 字段、事件消费、硬件、Flash、read-clear，是否可重入 |
| 内存/ABI | 初始化、对象寿命、alias、大小/对齐、外部布局与调用约定 |

新自有接口可采用 `ctx`、只读输入、时间/限制、输出的顺序；既有接口按项目/ABI 合同迁移，不能为了风格随意改函数形参顺序。返回值和 out 不重复表达同一个结果；若允许 input/output alias，明确相应行为。

示例仅展示签名完整度，不要求新增该类型或接口：

```c
bool charge_candidate_evaluate(charge_ctx_t *ctx,
                               const sample_snapshot_t *sample,
                               uint32_t now_ms,
                               charge_candidate_t *out_candidate);
```

公开头只暴露调用者需要的稳定类型/API和只读诊断。PI integral、搜索内部状态、只在本模块使用的 helper 留在实现或私有头。确有合法消费者的复位入口可公开明确生命周期合同；不能为了“私有”删掉原库必要 reset，也不暴露逐字段任意改写。

类型归真实 Owner：故障位归保护，阶段/档案归业务，硬件命令/状态归输出或驱动。不要因为某头刚好被包含就把类型放进去。

## 状态生命周期与并发

对可变 ctx 写清初始化、首次合法调用、重置、有效会话、失效点、实际写者/读者和调用域。ctx 不保存调用者栈上或短寿命对象的悬空指针。

按相关状态列清保留/清零/失效：

| 入口 | 例：需要分别判断的状态 |
|---|---|
| 初始化/校准 | 零点、采样窗口、旧候选、诊断与配置有效版本 |
| 阶段切换 | 积分、滤波历史、尾流端点、会话计量、当前批准 |
| STOP/故障/维护 | 候选、合闸请求、故障代次、恢复资格 |
| 换模式/平台/目标 | 参数派生、缓存、窗口、候选和等待中的输出 |

不要把所有入口收成一个语义不明的 reset，也不要未经合同清空应跨阶段保留的量。

源码证明单一前台写者时保留单写模型；不为假想多线程加锁或 RTOS。ISR/前台共享使用短临界区、快照、事件累计或代次，确保多字段一致与事件不丢失；`volatile` 不替代这些保证。

临界区保存并恢复原中断状态，不无条件开中断；不包含长计算、阻塞 I/O 或整个业务流程。ISR 不取阻塞锁。清故障或恢复时重新核实硬件状态、事件和代次，避免旧清除动作覆盖刚来的故障。

## 真源、预览与缓存

样本即时派生由相应事实 Owner 产生；消费者保留来源、单位、时刻和有效性。算法按实际接收样本推进的平均窗/积分历史仍归算法。即时值与历史结果不得为了“单一真源”强行合并。

共用计算前核对输入、时点、单位、有效性和算法相同；数值恰好相同的门槛不代表同一语义。限制前的事实和限幅后结果分别保留。

模式入口各自推进专属流程和状态，共用函数接受真正通用的输入或已选定参数。两个入口都转发 `core(mode)` 而全部模式逻辑仍混在 core，不证明职责迁移完成；也不要求仅有一个分支的简单函数必须拆开。

预览检查实际指针别名：临时 ctx 中的指针仍可能回写正式滤波/积分/锁存。预览不得写硬件，正式事件按合同只提交一次；明确同拍阶段决策、资格、批准与诊断分别用哪一版输入。

若原预览已修改正式状态，去掉写入可能改变控制结果。等价整理不能假称无行为差异；保留第一个差异，按 BUG 修复授权处理，同时继续独立等价部分。

缓存不是默认架构。只有收益明确、状态更少或调用预算确需时才采用，至少核对适用依赖：

- 样本序号、真实采样时刻、有效性、校准/滤波代次；重复旧样本不刷新身份。
- 模式、平台、档案、Demo/普通目标、温度与实时电压/电流。
- 限制使能、数值、来源、故障/维护/命令代次及安全复核时点。
- 初始化、重置、换档、设置提交、故障、停机后的清除或重算。

配置不变的派生参数可在完整配置提交时预计算；依赖实时量的值必须有更新时机。相同序号或相等的最终 min 不能代替完整输入合同。重复样本时是否保留、收紧或撤销旧候选需明确。

Host 双算、对照日志留在验证/观察路径。没有对应批准行为需求时，不把迁移对照失配新接成生产停波条件。

## 语义与数值边界

多个 bool 分别说明真/假含义、生产者、读取时点、消费者及其角色：事实、资格、命令、事件或否决。彼此独立的事实可以并列；互斥模式用显式模式表达，不从启动下限为零、目标为零等旁值推断。

`power_limit == 0` 的合法零、未启用、无效和要求停机必须按真实合同分开表达。外部编码维持协议，内部可使用明确模式/有效位/原因；最终数值和原因不能互相冒充。

连续时间绑定正确的端点：样本有效时间、真实传能时间和尾流资格时间分别处理。首帧建立端点；重复样本、坏间隔和缺样不能拼出连续资格。

计数乘周期、窄化或删溢出保护前，按支持范围推导整数提升、中间宽度和符号；需要加宽在运算前转换。核对乘除顺序、截断、饱和、无符号时间回绕范围及宏/类型变化后的上界。

## 消费者、诊断与简化

删除状态前列生产者和消费者：控制必需、协议/存储、已授权遥测、测试观察或只写副本。积分、缓存、seq、故障代次和时序记忆即使不导出也可能必须保留；已退役开发资产与现场诊断分开判断。

删除仅为旧测试暴露的镜像时，将测试转为必要内部或行为断言；保留用户需要的观测模式和最少有效字段，同步实际 receiver、标签、单位和编解码。不能一概删 diag，也不为旧夹具恢复无价值 API。

一行 helper 只有明确事务/语义边界、真实复用、硬件审计、平台隔离或必要测试入口才保留。恒 true prepare 先查全部返回路径和 caller，确认无失败合同后可改 void；保持写零、标志清理、自然更新和首/末脉冲顺序。

收口后检查新增 enum/action/flag/API 是否有实际生产者/消费者、是否永远常量、注释路径是否可达。安全否决检查 start、autostart、restart/recovery、PWM commit、relay close 和维护入口，不能只定义不消费。
