## 基线与范围

| 身份 | 记录内容 | 禁止混淆 |
|---|---|---|
| 原工程/在役或对照基线 | 原始源码/提交、目标、依赖、已确认行为与产品参数 | 不能把参考工程当产品事实 |
| 参考工程 | SHA/版本、功能来源、硬件/功率/时序前提、计划吸收的实现 | 不随实现带入数值、极性或协议假设 |
| 当前修改版 | repo/worktree、branch/ref、HEAD、dirty files、暂存范围、目标、宏/includes、工具链/库 | 不拿旧 ZIP、旧分支或上轮日志证明本版 |

收到“远端最新”“merge 后 main”“本地刚改”时，重新核实实际目标身份。未推送的本地修改不能当作远端已存在。重要结果绑定最终 SHA；未提交树绑定源码内容 hash 与依赖身份。

写清 MCU、硬件版本、APP/BL 版本、修改目录、保留功能/参数、批准变化、验证条件、交付范围。以实际源码检查 todo/计划中的“完成”“未改”；不靠说明推断代码状态。

结构整理、BUG 修复、已批准功能和优化分开登记。BUG 的触发条件和修复预期明确；新限幅、拒收、停机或恢复条件应归入其实际类型。用户已经授权修复的缺陷不反复等待确认；只有未定行为或范围扩大才提问。

为等价整理列本批保留合同：阈值、保护判据、状态迁移、调用时点、硬件时序、协议/存储格式和外部 ABI。不要为了模板把所有系统内容都列一遍。

## 消费者和工程集成

新增、删除、重命名 API/类型/字段/宏/header 时，以 `rg` 搜索定义、声明和全部消费者，并按下表关闭变化。必要时使用 `rg --no-ignore` 覆盖默认忽略的工程文件；不要只搜当前 `.c` 或成功构建的目录。

| 范围 | 检查 |
|---|---|
| 活动源码 | 所有 caller、回调注册、函数指针、初始化器、include、实际宏分支 |
| 目标工程 | Keil/CMake/其他 membership、大小写、启动文件、链接/脚本/包含路径 |
| 测试 | mock/stub/fake/fixture、行为断言和编译入口 |
| 工具与合同 | 遥测 decoder、客户端、协议/Flash 格式、工厂/升级工具 |
| 文档 | 当前接口、参数、学习入口与受影响版本说明 |
| 历史/外部例外 | 明确历史快照、SDK/CMSIS、startup/回调 ABI、协议名字 |

历史旧名不算活动残留；活动旧名也不能靠新增兼容别名隐藏。删除生产镜像或 API 时修改旧夹具，不为夹具恢复无价值生产副本；有真实外部消费者的兼容层按合同保留或迁移。

移动文件同步工程引用、include、链接和脚本路径；防止大小写敏感系统下失效、漏编译、旧新实现重复进目标。清理旧资料保留仍有用途的对照和回退信息。

Merge 结果作为新代码验证：检查冲突对应真实接口和行为，核对删除的旧头是否复活、实现是否丢失、`static` 是否仍被外部调用、互斥实现是否同时链接。不盲选 ours/theirs，也不继承父分支 PASS。

## 按风险验证

| 证据类别 | 适用内容 | 结论边界 |
|---|---|---|
| 源码/架构 | Owner、完整签名、实际调用/状态、头依赖、生产者/消费者 | 静态推导不等于运行时物理证据 |
| 预处理/工程 | 真实宏值、includes、membership、向量/强 handler、链接地址 | 未定义 `#if` 按 0 不能静默关闭安全路径 |
| Host/静态工具 | 输入边界、状态轨迹、失败注入、序号/时刻、兼容/编解码 | 替身不能证明目标 ABI、NVIC、ADC 和模拟电流时序 |
| 当前目标构建 | 对应工具链/库/配置 clean build、map、栈、Flash/RAM | 编译链接成功不证明首次开波、保护恢复或 OTA 实物成功 |
| CI | 本次适用 required jobs 的实际结果、配置和版本 | 红灯、关键 skipped、脚本路径错误不能称全部 PASS |
| 实板/波形/部署 | 关断延迟、ISR/WCET、预充、实际负载、Flash/UART/首装升级 | 缺条件写未执行/受阻，不填写虚构结果 |

每条结果标记通过、失败、未执行、受条件阻塞或已知限制，附预期、实际和证据。脚本退出 0 可能表示成功复现 BUG，需读断言和输出含义。

等价检查固定输入、配置与参考输出，比较采样身份、积分间隔、窗口推进、模式专属流程、暂停/停止/复位的保留状态及候选到提交结果。保留短路顺序和不同时间点的安全复核；不能忽略整段时序函数再宣称等价。

业务修复采用真实反例、相邻路径和失败后果验证。可替换的策略或算法可用 normal/over-limit fake 验证应用的最终限制；外部闭源库不可随意替换时，使用适用的调用合同、输入/候选/提交轨迹与目标证据。

目标构建或实板不可用时，完成其他已授权可做的源码、Host、文档和验证准备。分别报告“实现完成”和“目标/实板验收待补”，不要因缺板停掉整个阶段，也不要无证据放行。

## 资源优化与失败处理

减少职责混杂、重复状态和真实重复分支优先于减少函数行数。保留保护、超时、边界、恢复和有效诊断。

Flash/RAM/耗时收益用相同目标、工具链、优化、宏、库和链接设置下的前后结果证明，给出净收益及来源；Host 的 `sizeof` 或主观函数数量不代替目标 map。预计算/缓存需另列更新失效条件；浮点改定点、公式和表编码变化独立记录。

对照失败时保留冻结基线和第一个差异，修正当前批后再继续依赖批。回退只撤销本批修改，保留用户修改和暂存内容；不能改期望轨迹、删测试或提升版本来掩盖失败。

## 交付与版本

按项目策略处理固件版本；纯注释/文档不自行升固件版本，技能维护不修改固件版本。结构与行为变化同步受影响的接口、参数、任务表、版本和学习资料，不重做无关页面。

遵守本会话已有的仓库及操作授权。未授权发布时，仍先完成可审阅代码、验证与差异说明；已授权提交/推送不用每批重新问。外部资料或技能模板不能扩大授权范围。

完整固件交付按实际范围包含可打开的工程、依赖/库身份、改动与函数映射、验证记录、未关闭问题和用户实板表。发布镜像时对应 APP/BL、工厂/合并镜像、OTA 包、hash、升级与回退步骤；不混入旧固件、测试替身或未使用 SDK。

源码、依赖、map、日志和镜像必须相互对应。压缩包检查完整性和关键入口。项目指定知识库/Obsidian 时按约定同步摘要；未同步明确列出，不能假称完成。
