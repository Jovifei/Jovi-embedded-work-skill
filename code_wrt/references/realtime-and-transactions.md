## 采样与校准

原码交接、零点、工程量换算、滤波、极值、功率和快照有效性有明确 Owner。至少标识来源、单位、sequence、实际采集时刻、有效位及校准条件；只有新采集推进新鲜度。

同一统计窗的电流、功率、极值和有效样本数来自相容的数据。复采更换电流时重算/失效其相关量，或明确区分两个窗口；不能拼接后仍声称同一时刻。主循环重复消费快照不补造有效样本。

校准由明确启动/恢复流程调用，不在普通采样任务中因拆文件反复校准。换平台、重新校准、滤波变化时列出失效的历史窗口、候选和累计端点；用户有效保存配置不能被默认初始化覆盖。

ISR/前台交接确保快照多字段一致和序号对应。明确读前/读后新数据或事件到来的处理，不能只加 `volatile`。

## 时间、计量与看门狗

| 目的 | 正确依据 | 不接受的替代 |
|---|---|---|
| 超时/冷却/充电时长/上报 | 单调时间或真实 elapsed，说明回绕范围 | 主循环/任务调用次数 |
| 连续有效证据/滤波窗口 | 新且有效样本的数量与身份 | 漏服务后重复使用旧样本补次数 |
| 容量/能量 | 有效电流/功率、明确跨度和缺样策略 | 无限拿旧功率补积分 |
| 调试/遥测 | 带宽和时间预算 | 积压后集中补发阻塞控制 |

计量要明确首个端点、时间源、样本年龄上限、坏间隔、暂停/停机和缺样处理；按合同记录有界保持、丢弃/中断积分等策略，不擅选会改变结果的新规则。连续资格不能跨无效段拼接。

覆盖正常节拍、延迟服务、时间回绕、时源停止与恢复。bool tick 会合并事件时说明实际 elapsed 与服务丢失，不把“已取标志”当每个毫秒都处理过。

喂狗依据关键生产者和控制流程在规定窗口内推进，不只看主循环票据；也不要求每圈所有生产者都有新数据。时间源卡住时，不能用同一时源的零 elapsed 永远证明未超时，应有可独立判断的进展或硬件超时依据。

启动、校准、合法维护和 Flash 可采用专门策略，但写清进入/退出、总预算和失败路径，不给无限期豁免。WDT 活性、控制截止时间、tick 统计分别验证。新增软浮点、长循环、Flash 或大量日志时核对目标 WCET、栈/map 和主循环最久服务间隔。

## 中断与并发

触及异步路径时走完整链：外设中断使能 → NVIC → startup vector → 强 handler → 驱动处理 → pending/ring/回调/快照 → 前台消费者。弱默认死循环即使能链接也不是正确实现；按实际后果评估阻断。

ISR 可完成必要的标志、数据搬运、事件计数、快照、有界组帧和紧急关断；快速 ISR 不跑 MPPT、复杂应用状态机、Flash 写入或阻塞打印。ADC 等硬件等待允许有明确最坏预算、超时和安全失败路径的短等待。

回调注明上下文和 payload 生命周期。注册、弱符号或 read/take/pending 选已有简单机制；驱动只知道中性合同和 opaque ctx，不解析应用类型。普通下行命令直接调用驱动 API，不绕中断。

按保护实时性、采样截止时间和通信负载分配优先级，列出嵌套/共享状态和最大关断延迟；不以全部同级代替分析。具体数字来自目标 MCU/工程，不能抄用 C300。

临界区保存并恢复进入前屏蔽状态，范围短，不包 Flash、长计算或业务全程。软件清故障或恢复时再次检查硬件/事件/代次，避免旧清除覆盖新故障。

关键快速链结合本版 map 核对向量、调用函数、常量和编译器辅助函数。单入口放 SRAM 不证明整链可在 Flash 忙时运行。目标测量与 Host 替身分开报告。

## 功率提交与恢复

前台正常 PWM/功率继电器由输出职责统一最终审核和提交；策略提供候选、保护提供资格、界面提交请求。**硬件保护/驱动 ISR 紧急关断立即执行**，不等待输出任务，不在 ISR 调完整 output 状态机。

正常开通的唯一提交点与异步关断是不同方向的合法通道，不能因“多个写点”删去紧急路径。非功率 GPIO、Flash 和串口仍由其各自职责调用驱动。

在同轮最终功率提交前处理会影响输出的命令、STOP/维护、保护、恢复资格及候选。output 后不可再通过旧任务/请求合闸或开波；状态变化若发生更晚，要撤销候选并等待重新审核。

恢复核对故障锁存、采样新鲜度、维护/存储禁止、命令/候选/保护代次、所需硬件状态和并发窗口。保留有意义的写前/写后/恢复中断后复核及失败撤回，不能当重复判断合并。

写清 PWM 极性、CCR 与导通关系、关断值、预装载、死区、自然更新、首次发波和停波顺序。库 Duty、驱动设定、定时器生效值与引脚波形分别记录。

任何物理停波后的重启都核对旧候选和算法记忆。按工程合同经历关断生效、有效保护窗、安全首拍和受控建立输出；具体首拍/斜率不得从他项目套用。新增这些约束属于行为变化，验证候选与实际 CCR 的动态、限流/限压和闭环稳定性。

## CBC、预充与继电器

CBC 写清硬件触发/动作、软件事件与计数、锁止、扣分、恢复资格，区分逐周期硬件行为和软件重新使能。覆盖停波、首个恢复周期、连续/间歇故障和旧事件重放；不只测计数达到阈值。

当前 C300 的 ISR 关断，前台凭新候选恢复；不在 ISR 写 MPPT 库 Duty 或恢复 MOE。其他工程按各自批准合同，不把这一配置伪装行业通用值。

普通模式和 Demo 的预充/合闸分别列状态、等待、压差方向、超时和失败动作。公共操作可复用，资格不能无说明混用。

判断“停波后”“机械等待后”必须消费满足该时间关系的新样本；STOP、保护、维护和换档可取消尚未执行请求。请求和实际 GPIO 写入之间仍接受同轮否决。

ODR 只代表命令脚状态；无触点传感器不宣称机械吸合已确认。启动电压资格与触点实际完成使用不同语义。

## 配置与 Flash 事务

配置形成完整候选后再校验，按批准持久化/读回策略成功后原子发布有效版本。失败不可出现新平台/旧阈值、新模式/旧限制或部分生效；记录是否允许暂存但未生效。

区分可选记录缺失、可用旧记录和介质损坏。按合同用默认或有效旧值；不能证明安全有效时禁止功率，不静默清空用户数据掩盖写失败。

计量保存失败不提前更新已保存值/索引，不清待保存标记。涉及页搬迁、冗余、CRC、序号或 commit 标志时，针对各写入/擦除阶段失败注入并检查恢复；序号回绕按实际格式处理。

APP/BL 共用分区地址、页大小、镜像边界、格式和 CRC 定义保持单一来源。改 MCU/Flash/链接布局时核对两个目标、边界计算和部署工具，不能只改 APP。

Flash 维护前功率状态和喂狗策略按硬件合同进入；写入失败传播到真正的消费者。不能因 Flash API 返回后就假定持久化完整，也不能推进依赖失败记录的破坏性操作。

## UART 帧与 ACK

同时核对长度上限、字段间关系、完整帧边界、CRC/校验和和缓存生命周期。例如各字段分别未越界，仍要验证 payload 长度与 frame 长度减去头尾开销一致；处理加减溢出后再索引。

接收、冻结帧与发送缓冲各有容量、发布/消费时点和溢出策略；完整帧发布后不被下一半帧改写。有界 ISR 组帧允许，命令语义、配置提交和升级业务在前台。

保护关断不等待通信 ACK。按协议区分命令生效、ACK 入队、DMA/中断发送完成和对端接收；无确认机制不宣称对端已收到。复位/跳转前是否等待实际 TX complete 取合同，等待需有界失败策略。

## OTA 与部署

明确准备、持久状态、擦写、镜像校验、完成提交、结果发送、复位/跳转顺序。状态持久化失败时停止依赖其成功的下一破坏性步骤。

覆盖非对齐分片、重复/同镜像重入、断线续传、有限重试、校验失败、掉电恢复和版本回退。不能递归无限恢复，也不能重连就无限重置总预算。

BL 若新增完成记录校验，首装和工厂烧录工具也要生成合格记录，配套镜像完整性、向量/入口检查和恢复入口。记录格式/CRC取本工程合同，不统一套用某项目 DONE。

列出实际部署的新旧 APP/BL/配置格式组合、升级入口和降级行为。APP OTA 不自动升级 BL；若必须更换 BL，明确授权、工具、工厂包及恢复验证。已有升级通过不代表新板首装可启动。
