# 实时链与事务

处理实时、并发、采样、执行器、通信、存储或升级时读取。仅选与本批有关的部分；数值、函数、文件位置、上下文及恢复策略来自当前工程，不从示例推导默认方案。

## 采样与校准

按使用需求确定原始数据、换算、校准、滤波和统计的维护责任。数据应能够说明来源、单位、采集时刻或顺序，以及必要的有效性条件；不强制所有记录包含同一组字段。

关联统计量来自相容区间。更换部分数据时同步重算、失效或明确区分相关结果，不能拼接后仍声称同源同刻。重复消费不能冒充新采集。

校准触发、结果生效和历史失效按实际合同实现；一次性、定期或在线校准均可能合理，不能因函数移动改变其触发次数。配置变更不覆盖有效用户选择。

中断、任务或 DMA 之间的交接保持样本身份与多字段一致性。新数据到来、消费者延迟和溢出均有明确处理。

## 时间与进展

| 目的 | 应说明的依据 |
|---|---|
| 超时或等待期限 | 实际时间源、分辨率、回绕与最长间隔 |
| 连续观测条件 | 新且有效的观测身份、数量及间断处理 |
| 积分或累计 | 有效测量、真实跨度、单位与缺样策略 |
| 周期服务 | 调度保证、延迟或丢周期时的处理 |
| 健康监测 | 规定窗口内必须推进的工作及失败响应 |

不能把主循环次数当成真实时间，不能用重复旧数据补造新样本。固定周期积分可以基于已保证且验证过的周期；周期不受保证时应处理实际间隔和缺失段。

时源停止时不能用同一时源的零间隔证明未超时。启动、校准和维护的例外有进入、退出、总预算与失败路径；健康活性不等于满足实时截止时间。

对新增长计算、存储等待或日志，检查目标最坏执行时间、栈、可抢占性和其他工作最久服务间隔。不能只凭使用浮点或某个函数名判定必然超时。

## 中断与并发

按实际 MCU 和运行模型追完整异步路径：事件产生、使能与路由、最终入口、执行处理、交接、消费者。向量、函数声明或链接成功各自不能证明全链已生效；默认处理是否构成问题取决于实际链接与可达路径。

任何中断或严格实时上下文中的操作，都要满足预算、重入、可阻塞性和平台 API 约束。数据搬运、有界组帧、短计算、闭环更新或紧急关断是否可在该上下文完成，应由实际合同证明，不能机械规定所有算法必须移到前台。

回调注明真实上下文和数据寿命。选择现有适用的注册、事件、缓冲或读取接口；不为普通控制调用增加软件中断，也不为了模块分离另建回调框架。

优先级由时限、资源共享、嵌套和负载推导。不得照搬其他工程的优先级数字，也不得以全部同级代替分析。

临界区或锁的保护对象与期限明确。保存恢复原中断屏蔽状态；不在禁止阻塞的上下文等待。清事件、清故障或发布快照时检查竞争窗口，旧操作不能覆盖更新的事实。

若存在存储忙时仍须执行的快速路径，应结合本版链接结果核对入口、调用函数、常量和辅助函数；只移动一个入口不能证明整条路径可用。

## 执行器与恢复

先明确正常动作的决策、许可、提交与生效关系，以及多个入口的仲裁规则。具体职责可在一个模块或多个模块内完成，不要求固定名称和数量。

紧急动作按安全时限保留快速通道；普通状态更新不能覆盖较新的故障否决。集中正常写点可以帮助审计，但不能因此删除硬件或中断保护路径。

提交动作时核实其所依赖的许可仍有效。并发更新、维护或停止发生后，旧命令应按合同取消、重新审核或安全降级；不能假设“本轮较早已经检查”永远有效。

恢复说明触发条件、有效输入、锁存状态、硬件状态、并发仲裁及失败撤回。写前、写后和恢复中断后的检查可能保护不同窗口，删除前需证明其用途重复。

**功率控制示例，非默认实现：** 对使用 PWM 的执行器，可以核对极性、关断值、更新机制、首次发波和重启历史。若某项目规定周期保护或预充，还需验证对应事件、资格、延迟和恢复；不因该示例要求其他产品新增这些功能。

命令、寄存器设定、外设生效和物理测量是不同证据。没有反馈时不宣称实际动作已确认。改变启动限制、恢复斜率或延迟属于行为变化，需要相应依据与动态验证。

## 配置与持久化

定义完整候选、有效版本、持久版本及其提交关系。可以先持久化后生效，也可以按明确合同先临时生效再持久化；关键是原子性、失败回滚和对外结果一致，不能隐含混用不同版本。

区分记录不存在、旧格式、有效旧值和介质失败。默认值、保留旧配置或禁止相关动作按已确认策略执行，不能清空用户数据掩盖失败。

持久化失败不得提前推进已保存进度或依赖其成功的破坏性操作。多步骤写入需要校验、提交及断电恢复合同；对实际相关边界做失败注入。

跨组件或镜像共用的分区、格式、长度和校验保持一致来源。改硬件、存储布局或工具时核对全部实际消费者，不假设所有工程都具备相同引导结构。

## 通信与升级

通信同时验证容量上限、字段关系、消息完整性和缓冲生命周期。各字段分别未越界不代表组合合法，计算索引前检查溢出。

接收、发布和消费各有所有权及溢出策略，消息发布后不被后续写入破坏。组帧与命令处理的位置由执行预算和业务责任确定，不强制固定文件或调度方式。

区分请求接受、动作生效、应答排队、实际发送和对端确认。安全动作不能无界等待通信；复位或跳转前是否等待发送完成取实际协议，等待需有界失败处理。

升级流程应说明准备、擦写、校验、提交和切换关系，覆盖相关的首次安装、重复请求、断线、重试、掉电、兼容与回退。新启动条件同时检查生产烧录和维护工具。

分别验证实际新旧组件和配置组合。已有升级成功不证明首次安装可用；未涉及升级的任务不自动扩展成引导程序改造。
