# C300 实施边界

仅在任务明确是当前 C300，或明确采用该项目合同进行对照时读取。其他工程自行确认目标、参数、库和职责；不照搬这里的数值。开始时对照当前源码与用户后续决定，不能把历史待办视为仍存在或已修复。

## 当前工程身份和参数

分别保留原 AN300/C300 产品基线、B/165W 参考和当前修改版的源码身份。当前目标为 HT32F65240；换 MCU、编译器或库另列适配和目标验证范围。

| 合同 | 保留项 |
|---|---|
| 功率/电流 | PV 300 W、最大 10 A；电池 CC 6 A、涓流 2 A |
| PV 范围 | 13–55 V |
| 库比较计数 | 108–1092、周期 1200；真实导通关系按原硬件极性/模式 |
| 普通电池 | AN300 12 档、单位、温补、充电控制与保护关系 |
| 不迁入的 B 参数 | 165 W、7 A、5 A、8–90%、独立 90 V/95 V 门 |
| Demo | Lead 48/60/72 V 三平台；目标默认 57.8/72.3/86.8 V，普通档案独立保留 |

这些值来自已明确的项目约束，应用时仍核对当前版本。修改阈值或单位必须对应批准行为/BUG 依据，不能藏在搬文件、抽 helper 或参考代码吸收中。

## 六类职责落实到现有工程

| 职责 | 应实现 | 边界 |
|---|---|---|
| sample | 原码交接、校准、换算/滤波、极值/功率、快照/时效 | 不决定阶段或恢复功率 |
| charge | TC/CC/CV/FC、复充/限时/限功率、原库调用与复位、Demo 档案、候选和相关计量 | 不写寄存器、不处理 UART 字节、不越保护开功率 |
| protection | 判故障、锁止/恢复资格、供电/存储禁止和许可 | 不搜索 MPPT、不独立恢复输出 |
| output | 前台正常 PWM/功率继电器的最终审核、首拍/斜率、预充、维护关断 | 不制定电池参数、不改库私有状态 |
| debug | 诊断快照、限量日志和统计 | 不阻塞控制或改正常策略 |
| mmi | 按键/面板/命令语义、配置请求/完整档案提交、显示/OTA 交互 | 不直接合功率继电器或开 PWM |

main 管初始化、时间/节拍、顺序和健康。LED、按键、配置、变量定义、启动和中断等支持文件可保留。六类职责不意味着只能有六个 C 文件，也不要求为了每个表格角色再加 service/manager/DTO 包装。

保留合理的现有目录和函数，应用不无必要泄漏 HT32 头/SDK 类型，驱动不认识充电业务结构。硬件命令通过普通接口下行；驱动 ISR 事件/快照上行。紧急关断保留在硬件/驱动 ISR，正常功率由 output 本轮最后审核提交。

## 原 MPPT 库

直接使用 `HT32_Mppt_Solar.h` 对应既有库。应用计算调用和复位入口集中 charge；不吸收 B/165W 搜索算法，不加只做转发的多层 MPPT 门面。

核对头文件/库版本或 hash、函数完整签名、结构布局、参数单位、调用频率、编译器/处理器 ABI 和 reset 语义。不能以模板重定义库结构、重排成员、任意写私有 Duty 或修改不理解的内部状态。

候选与实际输出分别追踪。首拍、斜率、CBC、预充或采样期限即使保留原库也会改变闭环动态；通过候选/CCR 轨迹、限压/限流和目标测量评估，不能用“库没改”证明全部等价。

## C300 特定时序和状态

下表用于防止结构整理静默破坏当前合同，不替代当前源码、完整不等式和实测证据：

| 项目 | 当前合同摘要 | 实施检查 |
|---|---|---|
| IRQ | CMP=0、MCTM 更新=1、tick/UART=3 | 结合实际使能、嵌套、向量和目标最坏延迟 |
| 首拍 | 关波 1201，经两次成功自然更新到 1092，再经两次，复核后使能；两段各 3 ms 超时 | 自然更新、真实关断、资格与失败撤回；不能用软件赋值冒充已生效 |
| 运行斜率 | 合格新毫秒服务，增大导通方向最多减 6 比较计数；另一方向也受服务门约束 | 实际 elapsed、重复服务和候选/CCR 轨迹 |
| CBC | 保留 500 积分；ISR 关断，前台新候选恢复；停波/首个恢复周期不扣分 | 不在 ISR 改库 Duty 或开 MOE，防旧候选/同轮请求再开 |
| 普通预充 | 请求压差 2 V；停波后新样本；PB4 前 3 V/单向资格；100 ms 后 3.5 V；阶段 150 ms 超时 | 按当前合同核对精确不等式、样本时刻、取消与失败行为 |
| Demo 合闸 | 保留自身已确认例外 | output 执行前仍接受同轮停止/保护/维护否决 |
| PA15 | 当前异步 Boost 合同保持低 | 不因此声称电感始终 DCM |
| 采样期限 | 当前 1 ms 门 | 用执行时间、最坏服务和负载证据证明适用性 |
| BL 启动 | 有效完成记录、整镜校验、向量/入口资格 | 首装/工厂工具与现行 APP/BL 组合一起验证 |

## Demo、配置和部署

每个平台的 Demo 目标有独立配置归属，但可继续放在 charge/现有配置内，不为“独立”增加应用模块。尚未确定的面板入口、设置协议和退出交互保持需求待定，不提前扩展协议。

Demo 目标变化核对上下控制窗、功率/电流、软件保护与硬件比较器和可工作范围，不为达到目标直接放宽保护。默认只作初始值，不覆盖有效已保存设置；切换平台/模式采用完整档案事务。

APP/BL 共享分区与长度定义要一致；UART 不只查单字段上限，还查关系。新 BL 完成记录要求必须配套首装/工厂包和失败恢复，不把 APP OTA 成功当作 BL 或新板首装已通过。
